# 双版本文档逐字对账（HTML ↔ LaTeX 之类的平行文本）

## 一句话结论

**这种对账工具的头号敌人不是漏检，是自欺。** 归一化表只要多剥一点，什么都能"对上"，
门禁就变成永远绿 —— 比不挂还糟（它给了你虚假的安全感）。所以：
①**先看原文再判真伪**；②**归一化按整词替换**；③**回归件必须有"清空归一化表应重新报错"的判别性复算**。

## 触发场景

- 同一内容维护两份源（HTML + LaTeX / Markdown + Word / 双语版），**各自手工改、不重跑转换器**。
- 出现"这条只在纸本上有著录，网页版没有""改了一版忘了另一版"这类问题。
- 要给这类项目加一条"两版一致"的门禁。

## 为什么需要它（这条缺陷为什么只有它能抓）

两版手工同步 ⇒ 必然分叉。这一档缺陷的共同特征是：
**编译/构建 0 错、静态检查全绿、日志干净**，产物也出得来 —— 只有把两版文本**逐字对撞**才看得见。
实测（一本 12 章科普书）：首次对账即抓出 15 条，其中 11 条是真的（9 条"一边写了出版者/卷期页、
另一边省略"，2 条标点体例），全部在此之前一路绿灯通过。

## 第 0 步（最容易被跳过）：判真伪只能看**原文**

归一化后的输出是**加工品**，已经两次（第三次）造出假缺陷。任何"不一致"都必须先回原文：

```python
# 把两版的原始片段并排打出来 —— 不要凭归一化结果下结论
def dump(chapter, note_id):
    print("-- HTML 源 --"); print(html_note_raw(chapter, note_id))       # 含标签的原文
    print("-- LaTeX 源 --"); print(tex_notes_raw(chapter)[int(note_id[1:]) - 1])
```

判断口诀：**"命令 vs 它的渲染结果"是机制差异，"内容不同"才是分叉。**

## 归一化：三张表 + 一条替换纪律

### 三张表（缺一张就造假缺陷）

| 表 | 作用 | 不写会怎样（实测） |
|---|---|---|
| `SYM` | 命令名 → **渲染结果**：`\approx`→`≈`、`\cos`→`cos`、`\pi`→`π`，以及**项目自定义宏**（`\Rat`→`ℚ`，值抄自 preamble） | 命令名被整个剥掉：`\approx` 让 `≈` 凭空消失、`\cos\theta+i\sin\theta` 退化成 `θ+iθ`、`$\Rat$` 剥成空 |
| `BB` | 黑板粗体：`\symbb{Q}` / `\mathbb{Q}` → `ℚ` | 只剥命令名会留下裸 `Q`，与 `ℚ` 不等 |
| `WRAP` | 包裹式命令**去名留内容**：`\emph{} \text{} \mathrm{} \textit{} \textbf{}` | 连内容一起剥掉 |

### 替换纪律：**必须按"整词"**，不能盲目 `str.replace`

```python
# ✗ 错：for k, v in SYM.items(): s = s.replace(k, v)
#   `\left(` 会被 `\le` 咬成 `≤ft(` —— "长键优先排序"也救不了（\le 就是 \left 的前缀）
# ✓ 对：一次左到右正则扫描，命令名一次吃满字母
CMD = re.compile(r"\\[A-Za-z]+\*?")
s = CMD.sub(lambda m: SYM.get(m.group(0), m.group(0)), s)
s = WRAP.sub("", s); s = CMD.sub("", s)       # 剩下的未知命令再兜底剥掉
```

### 其他必须两侧对称处理的机制差异

- **自动编号 vs 手写编号**：`\noteref{...}`／`\figref{fig:N-M}` ↔ 手写「注 [4]」「图 3-3」。
  ⚠ 抹的时候**保留文字、只抹编号**（`注\s*\[\d+\]` → `注`）—— 整串抹掉会造出**新的**假缺陷。
- **不折行空格**：LaTeX 的 `~` 要在源侧剥掉（`注~\noteref{}` 抹完会剩孤零零一个 `~`）。
- **dash 形态**：`-`(ASCII，数学模式里渲染出来就是负号) 与 `−`(U+2212) 是同一件事的两种写法
  ⇒ 两侧都折成同一记号。**代价必须写进 docstring**：本工具**不覆盖 dash 形态**，
  那一档交给专门的标点/连接号门禁（区间必须 en dash）。
- **去空白**：最后统一 `re.sub(r"\s+", "", s)`。

## 抽取侧的三个坑（也会造假缺陷）

1. **HTML 切标签绝不能用 `<[^>]*>`**：属性值里含 `>`（`data-tex="2^n>n"`）会在属性内部提前收尾，
   把属性尾巴当正文 ⇒ 必须用**引号感知的标签扫描器**。
2. **剥注号只能剥注首那一个**：`<span class="num">.*?</span>` 会把**分数分子**的 `.num` 一起剥掉，
   造出假的"不一致"⇒ 用 `^\s*<span class="num">[^<]*</span>` 锚定行首。
3. ★ **同一个引号感知扫描器会把 `<script>` 当正文**（实测踩到）：脚本里的**比较运算符** `<`
   （`ci < C.length`）会被当成标签起点，然后一路啃到下一个引号才收尾 —— 夹在中间的一大段正文
   **被整块吞掉**。症状很反直觉：判据报「正文里找不到这句话」，你去 HTML 里一搜却在。
   修法：**先整块丢掉 `<script>`／`<style>`**（JS 源与 CSS 都不是正文）再剥标签：

   ```python
   t = re.sub(r'(?is)<(script|style)\b[^>]*>.*?</\1\s*>', '', t)   # 先剔整块
   ```

   附带后果与对策：剔完之后，**挂在脚本里的那类文字**（画布读数、动态提示）就不在"扁平正文"里了，
   要对它们判"是不是这么写的"就得**比源串**（`re.sub(r"\s+", "", html)`，不要过标签扫描器）。
   顺带一提，剔掉 script/style 后"正文"会显著变短（实测 32,525 → 17,896 字），
   这本身就说明**之前有近一半的"正文"其实是 JS 源码** —— 拿它当判据基准本来就不可靠。

## 回归件：两侧都验 + **判别性复算**（这条是灵魂）

```
[好样本]        现稿 → 0 条          证明它不是"见谁都 FAIL"
[坏样本·A 侧]   在 A 侧改一个字 → 必须报错
[坏样本·B 侧]   在 B 侧改一个字 → 必须报错
[判别性]        **清空归一化表 → 必须重新冒出 ≥3 条**
```

最后一条是**唯一**能证明归一化表"在干活、不是装饰"的断言 —— 少了它，
别人把表删空、工具反而"全绿"，你还以为一致。

### 写负样本时的新坑（实测）

- **注入要全篇替换，不能只替第 1 处**：锚点词往往在正文里先出现，只替第 1 处会改在正文上
  （而工具只看章末注）⇒ 负样本"抓不到"，看着像判据瞎了。
- **回归件输出要对齐父级解析器**：只认字面量 `[OK ]` / `[BAD]`，打成 `[好]/[坏]` 会显示
  "0 通过 / 0 失败"，像根本没跑。
- **回归件要让旧判据真的会判它 FAIL**（正样本要"判别性"），否则是空跑。

## 配套的补丁脚本纪律（改两版文本时）

- **同一文件的多个 `Edit` 不要并发**（会互相覆盖、却全报 `success`）⇒ 用一次性幂等补丁脚本：
  单次原子写 ＋ 逐串"命中次数"核对（幂等：已改过则命中 0，视为已应用）＋ 落盘前自检 ＋ 落盘后回读。
- ★ **自检必须比"差异"，不能比绝对值**：HTML 里有 `<style>`/`<script>`，花括号天然不平衡
  （实测 354/355）、JS 字符串里还有 `<sub>` 这种"标签" ⇒ 绝对判据**必然误杀**
  （首跑三个文件全被拦下）。正确做法：`err_before` 与 `err_after` 相等即通过，
  另外单独校验**新插入的片段自身**配平。
- 改前先 `cp` 备份到临时目录，改完跑对账 + 全稿验收两侧确认。
- ★ **双版共用一套模板时，用"命名占位符"，别用位置式 `%s`**：同一段文案要出 HTML 版
  （`<strong>`／`<i>`）与 tex 版（`\textbf{}`／`\emph{}`）时，各模板的占位符**个数往往不同**
  （实测同批里有 2 个的、也有 4 个的），`s % (a, b, c, d)` 会直接抛
  `TypeError: not all arguments converted during string formatting`。改成
  `s.format(B1=…, B2=…, I1=…, I2=…)` —— `.format` 对**多余的具名参数不报错**，一套函数通吃。
- ★ **要替换的段落中间嵌着标签时，整串 `replace` 找不到**（例："…排到第 `<span>n</span>` 行只能覆盖…"，
  两头是纯文本、中间是标记）。改用**区间替换**：起点串定位 `i`、终点串在 `i` 之后定位 `j`，
  做 `src[:i] + new + src[j + len(B):]`；自检里把"**区间起点命中数 == 1**"也核一遍
  （命中 0 视为已应用、命中 ≥2 直接拒并报错）。

## 方向选择：哪一版是"准"的

差异出现时先问"哪版更全/更权威"，不要默认改近的那版。

- 若**印刷版写全了著录、阅读版省略** ⇒ 改**阅读版**补齐。理由：阅读版往往是**转换源**，
  它不齐，将来重跑转换器就把著录丢了。
- 若**阅读版可见内容与它自己的 `data-tex` 不一致** ⇒ 那本身就是独立缺陷，按源修正。
- 一直改不动的项目，就把它固化成**体例**并写进正式文档（例：西文书名一律斜体、不用书名号；
  数学标记内并列分隔用逗号不用顿号），下一章照抄。

## 交付前自检清单

- [ ] 对账工具退出码 0，且逐章打印"逐条逐字一致"
- [ ] 回归件 4 项全 `[OK ]`（含判别性那条）
- [ ] 全稿验收基线数与改动前一致（没被改坏）
- [ ] 工具已挂进正式验收入口（否则没人跑）
