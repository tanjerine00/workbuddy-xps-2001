# 港股个股数据库审计与升级

## 何时用

- 用户投来一份港股（或 A+H）个股的 Excel 数据库，问「有没价值 / 完善起来 / 审计一下」
- 需要为港股个股建立日线、卖空、A/H 溢价序列
- 需要判断某个"新维度"能不能进信号体系

## 铁律（沿用本项目用户定调，不得例外）

1. 任何进结论的数据 **≥2 独立源交叉**；单源显式标注「未交叉验证」
2. 两源冲突 → **如实并列，不取平均、不插值、不取中间值**
3. **查不到就写"查不到"**，绝不用估算填补缺口
4. 事实与判断分开写；关键数字注明统计期、截止时间、来源
5. 不预测股价点位、不承诺收益、不给买卖/仓位指令

## 一、先判"这份文件有没有价值"——三条线

| 线 | 怎么判 |
|---|---|
| **价格线** | 能不能找到 ≥2 个独立源逐字段对齐。对齐得上 → 真的，可直接用 |
| **维度线** | 有没有出现你体系里**原本没有**的维度（港股每日卖空、A/H 溢价、CCASS…） |
| **错误线** | 反向找错。**第三方文件的错误密度本身是重要信息** |

> ★ 经验：有价值的往往不是它填好的部分，而是**它带来的新维度与一排错**。
> 错误里最值钱的是"看起来更漂亮、实际错"那一类。

## 二、港股日线的两个源（含坑）

### 源 A：新浪（通过 akshare）
```python
import akshare as ak
df = ak.stock_hk_daily(symbol="00981", adjust="")   # 不复权，返回 2004 年起全历史（约 5535 行）
```

### 源 B：腾讯（**必须分段**）
```
https://web.ifzq.gtimg.cn/appstock/app/hkfqkline/get?param=hk00981,day,{start},{end},640,qfq
```
- ★ **单请求只回 640 行**。要长序列必须切成多段（如 2019-12~2022-06、2022-07~2025-02、2024-02~2026-09），
  再单独补一段覆盖段间缺口。段数不够会静默少行，**必须逐段核对首尾日期**。
- 返回 `data.hk00981.qfqday`（前复权）。

### 源 C：东财
- `push2his.eastmoney.com` 的港股日线 **HTTPS 被重置、明文 HTTP 也常常拿不到**。
- 东财可靠的是 **实时 `push2`**（当日 OHLC），适合做当日锚点交叉，不适合长序列。

### 判定口径（关键：区分"错"与"源差异"）
1. 逐字段比对（最高/最低/成交量/成交额 **零偏差** 才算硬）
2. 少数不符日 → 拉第三个源对撞
3. **7 个不符日里 7/7 都能被第三源解释 → 是源差异，不是错误**。这一步必须做，
   否则会把"不同复权/不同数据商口径"误判成"数据造假"。

### 附带验证（便宜且很有力）
- 总股本列的变化日 + 变动股数，去和**公告口径**（重组/增发预案）对撞。
  本例 2026-06-23 由 8,013,495,877 → 8,560,677,950（+547,182,073）与《重组报告书》发行股数**精确一致**。
- A 股列（若文件含A股）与自建 A 股日线比对：重叠期收盘最大偏差应为 0.0000，首日应等于该股上市日。

## 三、港交所每日卖空：怎么自证真伪

字段：`Short_Turnover`（卖空成交额）、`Short_Volume`（卖空股数）、`Total_Turnover`（总成交额）。

**核心恒等式检验（最重要）**：
> `Short_Turnover ÷ Short_Volume` ∈ 当日 `[Low, High]`

- 全部交易日通过 → **数据与单位同时自证**（单位错了不可能落区间内）
- 本例 594/594 天零越界。
- ★ 注意两列覆盖天数可能不同（本例 Short_Turnover 735 天、Short_Volume 594 天，
  后者只到某个日期）→ **比值只能在两列都有值的交集上算**。

派生：`Short_Ratio = Short_Turnover / Total_Turnover` + 5/20/60 日滚动均值。

### 卖空（流量）≠ SFC 淡仓（存量）
- 卖空 = 每日成交里的空头流量（港交所）
- SFC 淡仓 = 双周申报的未平仓空头存量
- **两者不可互相代证**。本例 2026 年卖空年均 9.69%（全序列最高）而 SFC 淡仓 0.804%（三个月最低）
  → 流量放大、存量收缩。任何空头判断必须写明用的是哪一种。

## 四、A/H 溢价率

```
溢价率 = A股收盘(CNY) ÷ (H股收盘(HKD) × HKD_CNY) − 1
```

- 正数 = A 股贵于 H 股。
- ★ **汇率陷阱**：若拿不到逐日 USDCNY（本机通道常拿不到），只能用固定汇率。
  常用 `0.9180 ≈ USDCNY 7.16 ÷ USDHKD 7.80`。
  **代价**：2020 年人民币兑港元约 0.885，用 0.918 会把 2020 年溢价**高估约 3.6pct**。
  → 必须在报告里写明"固定汇率、非逐日"，并说明偏差方向。
- ★ **A 股停牌期必须剔除**：港股正常交易而 A 股停牌时，A 股列为空，
  直接相减/相除会出 NaN 或错值。

## 五、第三方 Excel 的 12 类典型错误（逐条查）

| # | 错误 | 怎么查出来 |
|---|---|---|
| 1 | **用港元汇率 7.8 折美元冒充人民币** | 查**文件内部恒等式**：`人民币营收 ÷ 7.8 == 文件另一处记的美元营收`。逐季对官方人民币口径算"等价汇率"，若落在 7.72~8.02 → 系统性高估 7~11% |
| 2 | `Net_Profit` 实为**含少数股东损益**却未标注 | 与官方"归母净利润"对撞（本例差 111.9%） |
| 3 | 同一期间**单季行 + 累计行重复** | 按日期 groupby 查重复 |
| 4 | `Report_Type` 把单季季报标成「Q4/Annual」 | 数值与报告期对不上 |
| 5 | **PE = 港元价 ÷ 人民币 EPS**（币种混算） | 看公式引用列；PE 会系统性高估 8~9%。PB/PS/EV 同病 |
| 6 | **分位公式整体错位** | 逐列读公式：`PE_Percentile` 无公式、`PB_Percentile` 引用 PE 列、`PS_Percentile` 引用 PB 列… |
| 7 | 分位区间与可得区间不符 | 股本列只 702/1635 行，却做"5 年分位" → 57% 是空区间 |
| 8 | `Cash` 语义错（例 `=Investing_CF − Free_Cash_Flow`） | 看公式定义，不是科目对不上 |
| 9 | 把 **6 个不同量纲**的增长率直接算术平均成 `Fundamental_Score` | 看公式；均值无意义 |
| 10 | 合成分量**未归一化**，阈值就凭空写死 | `Price_Score = AVERAGE(价格相对250日均价, −卖空比例)` → 0.25/0.1 阈值无标定依据 |
| 11 | **公式列无缓存值** | `openpyxl.load_workbook(f, data_only=True)` 全返回 `None` → 任何非 Excel 工具读出来都是空。**必须同时用 `data_only=False` 读公式串，才能判断这一列"是空的"还是"是公式"** |
| 12 | 要求填**结构性不存在**的字段 | 例「先进制程占比 / 12-14nm 产能」——公司从不按制程披露，任何数据商都不可能有 |

**读 Excel 的正确姿势**：
```python
wb_v = load_workbook(f, data_only=True)    # 缓存值（可能全 None）
wb_f = load_workbook(f, data_only=False)   # 公式串
# 两本对照，才能区分：真空 / 有公式但无缓存 / 有值
```

## 六、新维度裁决：能不能当信号（三步，缺一不可）

沿用审 A 股融券的同一套方法。

### 1. 非重叠采样
前向收益会让相邻交易日样本高度重叠。**必须隔 N 日取一次**
（T+20 → 每 20 日取一），否则会把 182 个重叠观测当成 182 个独立证据。

### 2. 因果方向（识别伪相关）
同时算：
- 水平值 vs 未来 N 日收益
- **变化率** vs 未来 N 日收益

> **若两者符号相反 → 伪相关**（序列单调趋势造成的假相关）。
> 本例 A 股融券：水平 −0.527 / 变化率 **+0.283** → 符号反转 → 伪相关，不可用。
> 本例港股卖空：水平 −0.123 / 变化率 **−0.161** → 同号 → **不是伪相关**。

### 3. 事件化（决定成败的一步）
- 连续触发合并为 1 个事件，取首日
- 阈值建议取**前 20% 分位**
- 算**相对所在年度基准的超额**（不是绝对收益——标的长期上涨时任何信号都"看起来有效"）
- 必做**极端值敏感性**：剔除最大 1/2/3/5 个事件后看超额是否翻负

> 本例判读：均值 +3.02% 但**中位 −0.49%**、胜率 50%，剔除 3 个极值后转负，2024 年 −3.47%
> → **裁决不可用**。它是"当日情绪的描述"，不是领先指标。

## 七、不要生产合成评分（除非三条前提都满足）

原文件的 `价值评分 / 市场评分 / 价格价值偏离` 方向没错，但前提是：
1. 各分量**已归一化**（量纲、量级都不同不能直接平均）
2. 权重**经回测校准**（不是设定出来的）
3. 有**证伪条件**

三条不满足 → 按铁律**未校准的合成指标不得作为信号**。登记为待办，不要硬凑一个能填满的格子。

## 七·补、通用：任何「第三方导出表」的核证口径（2026-09-22 实战新增）

> **适用范围不限于港股**：A股 股本/解禁/财务指标/股东户数等第三方导出表（妙想Choice、券商终端、
> Choice、Wind 导出）都走这一套。用户原话「**看有没价值**」= 走本节。

### 1. ★ 先探格式，别假设后缀
`.xls` 可能是：真 OLE2/BIFF8 ｜ xlsx 改名 ｜ HTML 表格存成 .xls（券商终端常见）。
```python
io.open(p, "rb").read(16)   # b"\xd0\xcf\x11\xe0\xa1\xb1\x1a\xe1" = OLE2(真 BIFF8)
```
- **读 .xls 用 `xlrd`**（openpyxl 只支持 xlsx）；`xlrd>=2.0` 仍支持 xls。本机装：`python -E -m pip install xlrd`。
- **★ 日期常常是「文本」不是 Excel 日期型**：BIFF8 里 `cell_type` 会是 `XL_CELL_TEXT`，
  值形如 `"2026-09-10"`。只判 `XL_CELL_DATE` 会得到**全 None**（曾据此误判「文件无日期」）。**两种都要兼容**。
- 导出表的**首行/首列可能是空占位**（`col0 = ""`、`row0 第一格空`）→ 指标行与日期列都可能整体**错位一格**，
  必须先用「合计 == 分项之和」这类**结构恒等式**验证对齐，再取数。

### 2. ★ 核证判据：对**已钉死值逐位复现**，不是"差不多"
拿项目里**已经钉死、有来源**的数去对撞，要求**逐位（到个位）一致**。
- 例：股本 8,562,264,585 股 / 25.46744622 亿股 —— 差 49 股也算**不一致**，要如实写。
- 反例警示：导出 xls 若精度只到「**万股**」，**它根本做不了逐位对撞** → 结论只能是「量级吻合，精度不足」。

### 3. ★★ 「同厂商 ≠ 独立源」——本节最容易犯的错
**妙想Choice 与 东财 datacenter-web 同属东方财富系**；两者逐位一致是**同源应有的表现**，
**不构成铁律要求的交叉验证**。必须另找**跨厂商**的腿（万得 / 新浪 / 腾讯 / 交易所官方）。
> 判据：先问「这两个源背后是不是同一个数据库」；是 → 记「未独立复证」，继续找。

### 4. ★ 源端的「占比/比率」字段一律自算
实测两例：
- 某导出表把「**占总股本比例**」的**分母写成了 A 股数**（2021-07-16 解禁行：写 40.0000%，真值 9.0558%）。
- 另一家同一字段也**行间不自洽**（同列有时 ÷现有流通股、有时 ÷解禁后流通股）。
**规则**：占比/比率**只用原始数量自己算**，并**逐个写明分母**（同一件事常有 3 个分母：总股本 / 该类别股数 / 该类流通股，差值可达数倍）。
若两源冲突 → **如实并列，禁取平均**。

### 5. ★ 判「当核证基准」还是「当持续投喂来源」
导出表是**人工快照**，会过期。**先去找它的机读上游**：
- 东财 `datacenter-web.eastmoney.com/api/data/v1/get?reportName=…`（**HTTPS 在本沙箱可用**，与 push2his 的 HTTPS 被重置不同）；
  股本事件 `RPT_F10_EH_EQUITY`、解禁 `RPT_LIFT_STAGE`；按 `filter=(SECUCODE="…")` 过滤。
- **判据**：机读源若**覆盖更长 + 精度更高 + 可自动重跑** → 导出表**降级为核证基准**，
  明确告诉用户「**不用再持续投喂**」（唯一例外要写清：机读源缺的那一小块）。
> 实例：东财 184 行（2019-12-31 起 / 股级）完胜某 xls 156 列（2021-01-05 起 / 仅万股）。

### 6. ★ 分清「事件驱动序列」与「零缺口日频序列」
**每一次变动一行**（股本变动、限售解禁、停复牌、分红）= **事件台账**：
- 完整性判据是「**每个事件都在**」，**不是**「每天都有」；
- **不得**用于滚动窗口统计 / 分位 / 相关性（分母不是交易日）；
- 登记时要写明这一条，否则下游会误用。

### 7. 交付物三件套
① 核证报告（`数据/<主题>_核证_<日期>.md`）：结论先行 → 对撞表（逐位）→ 口径纠错 → 边界 →
**待拍板选项**；② 抓取件（可重跑，**断言失败即非零退出**）；③ 元数据（sha256 / 行数 / 区间 / 自检结果 / 边界）。
> **口径若与旧记录冲突 → 必须回头订正旧记录**（活文档改、历史日志只加留痕），不能只在报告里写一句。

## 八、交付标准

1. **原文件不动**，产出 `_v2核证版.xlsx`（新增 `00_说明与核验` 页：逐表核验状态 + 错误清单 + 不可得项 + 来源路径）
2. 修正方式：**公式列替换为实测值**（避免依赖 Excel 重算），并新增列把口径写明
   （如 `Turnover_Denominator` 写明换手率分母是流通股还是总股本；`Source` 标注每行来源）
3. 同步导出 CSV（便于脚本消费）
4. **交付前自检要是断言，不是"能打开"**：结构 + 逐表自洽 + 独立复算一致
   （本例 40 项：VWAP 落当日[低,高] 逐行、MA250 抽查点与独立复算一致到 1e-9 等）
5. 不可得项**如实留空 + 注明入口**，不用估算填

## 九、环境坑（Windows + WorkBuddy 沙箱）

- 腾讯 kline 单请求 640 行上限（见 §二）
- `python -E -c "…"` 里别放反引号；stdout 默认 GBK，**必须在脚本里 `sys.stdout.reconfigure(encoding="utf-8")`**
- **JS 字符串里别写 Windows 路径**：`C:\Users\...` 会被 JS 转义吃掉（`\U`/`\z`/`\C`），
  页面渲染成 `C:Userszyx32...`；`node --check` **抓不到**，只有真跑页面才看得见 → 用正斜杠或 `\\`
- 写 .md 时**保留原换行风格**（混用 CRLF/LF 的文件统一 `newline="\n"` 会把整文件改掉）
- 同一文件多处改动 → 用**一次性幂等补丁脚本**（marker 判已应用 + 命中次数断言 + 回读复核），
  不要在同一消息里发多个 Edit（会并行互相覆盖，且都报 success）
