# A 股数据抓取与交叉验证（东财优先）

## 何时用

- 用户要求抓 A 股（尤其科创板/创业板）的行情、资金流、筹码分布、股东户数、龙虎榜、大宗交易、融资融券
- 用户说"数据要交叉认证 / 数据准确是第一要务 / 尽量用东财数据 / 万得第二优选"
- 发现某个数据源"拿不到"，需要先判定是**真拿不到**还是**请求方式问题**

## 铁律（用户定，不得例外）

1. 任何进入结论的数据 **≥2 独立源交叉**
2. 单源数据**显式标注「未交叉验证」** + 写明来源
3. 两源冲突时**如实并列**，**禁止取平均 / 插值 / 取中间值 / 挑有利的**
4. 容差只用于**判定一致/不一致**，**不用于平滑或修正**
5. 文本类（新闻/公告）必须验日期，并与行情数据交叉（"停牌/大跌 X%" 这类描述要能在行情上对上）
6. 冲突无法解释 → 结论降级为【暂无法判断】，写明还缺什么

## 数据源优先级

**东财（主）→ 万得（次，需终端+授权）→ 新浪/腾讯（交叉验证）**

## 关键坑一：东财 push2his 的 HTTPS 被掐，HTTP 可用

实测（2026-09-19）：同一 URL
```
https://push2his.eastmoney.com/api/qt/stock/fflow/...  → 15/15 全 ConnectionError（TLS 被重置）
http://push2his.eastmoney.com/api/qt/stock/fflow/...   → HTTP 200，真实数据 ✅
```
**不是间歇性抖动**。做法是全局 monkeypatch，**必须在 import akshare 之前打补丁**，
否则 akshare 内部的 `stock_cyq_em`（筹码）等仍走 HTTPS 而失败：

```python
import requests
_DOWN = ("https://push2his.eastmoney.com", "https://push2.eastmoney.com",
         "https://push2delay.eastmoney.com")
_orig = requests.Session.request
def _patched(self, method, url, *a, **kw):
    for h in _DOWN:
        if url.startswith(h):
            url = "http://" + url[len("https://"):]
            break
    return _orig(self, method, url, *a, **kw)
requests.Session.request = _patched
requests.request = lambda m, u, **kw: requests.Session().request(m, u, **kw)
# 之后才 import akshare
```

**`datacenter-web.eastmoney.com` 走 HTTPS 是正常的**，不要一起降级。

## 关键坑二：沙箱代理挑主机，"直连档"要删环境变量

环境预置 `HTTP_PROXY=http://127.0.0.1:24820`。它**按主机挑**：datacenter-web / 上交所 / 新浪 /
腾讯能过，`push2his` 走代理直接被拒。
**只设 `NO_PROXY="*"` 是无效的**（urllib 的 `proxy_bypass` 不认这个通配符）——必须：

```python
KEYS = ("HTTP_PROXY","HTTPS_PROXY","http_proxy","https_proxy","ALL_PROXY","all_proxy")
for k in KEYS + ("NO_PROXY","no_proxy"):
    os.environ.pop(k, None)     # 这才是真直连
```
需要回退代理时再把原值 update 回去。**任何抓取脚本都应"直连 → 代理"轮流重试 3–4 轮。**

## ★ 坑三：上交所融资融券的"分页陷阱 + 慢"（2026-09-19 实测）

两个坑连着踩，都必须绕开：

1. **akshare 的分页陷阱**：`ak.stock_margin_detail_sse(date=...)` 每次只取**第 1 页**，
   而服务端把 `pageHelp.pageSize=5000` 实际截到 **2000 行**。沪市两融标的两千多只，
   按默认排序个股**根本不落在第 1 页** → 逐日循环 127 次**全部命中 0 行**，
   而且不会报错，只会给你一张空表。**看到"0 行命中"先怀疑分页，别怀疑网络。**
2. **正解**：直接打官方接口并传 `stockCode=<6位代码>`：

   ```
   https://query.sse.com.cn/marketdata/tradedata/queryMargin.do
     ?isPagination=true&tabType=mxtype&detailsDate=20260918&stockCode=688981
     &beginDate=&endDate=&pageHelp.pageSize=5000&pageHelp.pageCount=50
     &pageHelp.pageNo=1&pageHelp.beginPage=1&pageHelp.cacheSize=1&pageHelp.endPage=21
   ```
   `Referer: https://www.sse.com.cn/`。返回 `result[0]`，字段：
   `opDate, rzye(融资余额), rzmre(融资买入额), rzche(融资偿还额),
    rqyl(融券余量·股), rqmcl(融券卖出量), rqchl(融券偿还量)`。
3. **慢**：单请求约 **8 秒**（服务端限速），串行 127 天≈18 分钟。
   → **必须并发**：`ThreadPoolExecutor(max_workers=8)`，实测 **127 天 1 分 11 秒**，
   命中 127/127、零失败。每请求别加 sleep（本来就慢）。
4. **强校验（必做）**：`融资余额(t) − 融资余额(t−1) == 融资买入额(t) − 融资偿还额(t)`。
   实测 120/126 天严格成立，6 天偏差（最大相对 0.125%），成因未明（疑标的证券调整/
   非交易过户/转融通）→ **如实列出，不平滑不修正**。恒等式大面积不成立才算字段理解错了。

## 易错点（都踩过）

- **新浪资金流的 `asc` 参数**：`asc=1` 返回**最早**的 num 条（会筛出 0 行），要最新必须 `asc=0`。
- **新浪资金流的 `changeratio` 是小数**，要 ×100 才是百分比。
- **新浪资金流 `turnover` 字段口径不明**，**不要当换手率用**。
- **东财资金流是 13 个字段**，顺序为
  `date, 主力净流入, 小单, 中单, 大单, 超大单, 主力占比, 小单占比, 中单占比, 大单占比, 超大单占比, 收盘价, 涨跌幅`。
  请求 f51..f65（15 个）会多出 2 列全 0。**内部自检：大单+超大单 == 主力净额**（应逐日成立）。
- **东财 `kline/get` 有时返回 `data:null`**，别硬拼参数；日线优先用已有的妙想底稿。
- **`ak.stock_hsgt_individual_em` 返回的是陈旧数据**（实测只到 2024-08），拿不到近期陆股通，须标注不可用。
- **数据回溯深度不同**：东财资金流只回溯约 120 个交易日；东财筹码分布只有近 90 个交易日。
  **必须写出实际覆盖区间**，不能让使用者以为有整段历史。
- 妙想 MCP **积分会耗尽**，耗尽后要立刻降级到 akshare/直连，不要卡住。
- ★ **日线序列里有「停牌占位行」**：停牌期间仍保留日期行，**开高低收全相等、量额为 NaN**
  （实测中芯国际 2025-09-01~09-08 停牌 6 天，因中芯北方收购）。
  → **任何滚动求和/滚动 VWAP 前必须先剔除 `volume` 为 NaN 的行**，否则 `cumsum` 之后
  整段变 NaN（表现为「250 日 VWAP = nan」）。剔除后「N 日」＝ N 个**实际交易日**。
  → 新浪/腾讯 K 线**不返回**停牌日，所以与妙想**行数天然对不上**，**不是数据错误**。
  → ★ **但腾讯会在「港交所停市日」补占位行**（开高低收全等、`volume = 0`），与东财「无行」形态不同
  ⇒ 做交易日集合对撞前**必须先剔腾讯占位行**。实测港股 2023-07-17（台风泰利）／2023-09-01（十号飓风苏拉）／
  2023-09-08（黑色暴雨）三日即此形态：**东财无行、腾讯有量为 0 的占位行 ⇒ 双源一致，是真停市，不是缺数据**。
- ★★ **东财 push2his 日线的 `volume` 单位是「手」，不是「股」** —— 建 `VWAP = 成交额 ÷ 成交量` 前**必须 ×100**，
  否则 VWAP 是真实值的 **100 倍**。
  → **这是最易静默通过的一个坑**：「VWAP ∈ [low, high]」自检能抓到（×100 必越界、不乘恰好落在区间内，
  实测 1462/1462 vs 0/1462），**但如果目标文件用「手」、参考文件用「股」，逐值对撞会给出 100 倍量级偏差**
  ⇒ **此时先怀疑单位，不要先怀疑数据错**。
  → **单位不是「A 股一律 ×100」**：实测中芯 688981 东财 push2his **须 ×100**；
  港股 00981 同一接口 `volume` **本为「股」，不可乘**。**逐标的实测，不要套模板**。
- ★ **腾讯 `ifzq` 日线 `cnt` 参数有上限**（实测单请求约 2000 行封顶）⇒ 取**全区间**必须**分段并接**，
  段间边界**去重**。**全区间一次请求会静默返回 0 行** —— 不要误判成「腾讯没有这只票」。
- ★★ **「零缺口」的正确判据不是「相邻交易日间隔 ≤ N 天」** —— A 股春节/国庆天然 5~11 天间隔、
  港股遇台风/黑色暴雨会**全日停市**，按间隔天数判会**大量假报缺数据**（实测 A 25 处、H 14 处全是正常休市）。
  真判据 = **「合并文件的交易日集合 == 独立第二源（剔除其占位行后）的交易日集合」**，
  用 `set` 做**对称差**，两边都必须为空（实测中芯 A **1495==1495**、H **1530==1530**，零差异）。
  → 报「零缺口」时**必须写明用的是哪一个判据**。
- ★ **东财「股东户数」是 A 股口径，定期报告「股东总数」是 A+H 口径**：
  中芯 2026-06-30 东财 287,089（A 股）vs 半年报 296,744（总数，含港股 9,655）。
  → 两份材料户数对不上时**先比口径**，别急着判谁错。
- ★ **VWAP 的分子（成交额）拿不到第二源**：新浪、腾讯的日线接口**都不含成交额字段**，
  所以 VWAP **无法两源独立复算**。可用替代检验：逐日 `成交额 ÷ 成交量` 必须落在
  当日 `[最低价, 最高价]` 内（实测 1462/1462 零越界）。
  **这能排除单位/缩放错误，但不等于交叉验证** —— 报告里要写清这个边界。
- **东财龙虎榜字段「成交额占总成交比」本身已是百分数**（如 16.4964），再 ×100 会得到 1649%。
  用断言防住：`龙虎榜成交额 ÷ 市场总成交额 × 100 == 该字段`。
- `np.array_split(df, 4)` 返回的是 **ndarray 不是 DataFrame**，再 `s["low"]` 必报 IndexError
  → 要切**位置数组**：`np.array_split(np.arange(len(df)), 4)` 再 `.iloc[idx]`。
- 报告正文里**不要写死数字**（如"穿越 10 次"），一律 f-string 引用变量，否则改了计算
  正文就自相矛盾。

## 必须产出的两样东西

1. **抓取脚本**：多源 + 通路回退 + 缓存（文件已存在就跳过）+ **逐项隔离**（一项失败不中断整批）+
   把失败原因写进日志。绝不重复打接口。
2. **交叉验证器**：逐日逐字段对齐 → 算偏差 → 与容差比 → 输出报告。
   价格容差 0.5%、成交量 1%。报告必须含：
   - 每对数据源的「比对日数 / 一致 / 不一致 / 最大偏差 / 结论」表
   - 超容差的**逐日明细**（不是只给个总数）
   - **单源数据登记表**，明确标「未交叉验证」
   - 冲突时写清两套数字及差异，**不给中间值**

## 判定"两源冲突"时先问一句：是数据错，还是口径不同？

不要一看到不一致就判"某源有错"。**先做字段两两对撞**（方向一致率 + 相关系数 + 比值中位数），
看是否存在某个字段组合能把一致率显著拉高。实测案例：新浪资金流 vs 东财资金流，
四组配对**无一达 90%**（最佳 75.0%、相关 0.81）——这不是数据错误，是**两家"净额"定义不同**。
此时正确做法是：**选定一家口径并固定下来（东财优先），另一家降级为"趋势弱参考"，
并承认该数据实质是单源**。同时用**来源自身的内部闭合性**独立验收（如东财四档合计 ≈ 0）。

反过来，如果一个字段的偏差比值是**恒定常数**，那是**复权口径差异**（除权除息），不是错误；
**非常数**才是字段本身不可靠。实测案例：新浪资金流的 `close` 字段有 4/127 天偏差 0.78–1.02%，
比值 0.9898–0.9922 非常数 → 该字段不能当价格源。

## 交付时怎么标注

- 通过三源验证的（如日线开高低收）：可写「已交叉验证」
- 只有一源的：写「【已确认】东财单源，未交叉验证」
- 口径不同的：写清两套数字与差异，注明"只用其一"
- 拿不到的：**明说拿不到**，不给"合理估算"填补

## 万得（Wind / Wind Alice MCP）取数：单位陷阱与能力边界

`mcp__wind-finance__*` 系列工具用自然语言问句取数。与东财/新浪不同，它的**返回值里
`unit` 字段不可信**——这是在补中芯国际五个缺口时实测踩到的，代价是可能差 7 倍。

### ★ 坑 1：同一张返回表里，列与列的单位可以不同，且标注可能是错的

实测同一次 `get_stock_fundamentals` 返回：

| 列 | 标注 | 实际 | 判定依据 |
|---|---|---|---|
| 营业收入 / 固定资产 / 在建工程 / 累计折旧 | 亿元 | 亿元（人民币）✅ | 与公告 6,732.3 百万对撞 |
| 归母净利润 / 少数股东损益 / 研发费用 | 亿元 | 亿元（人民币）✅ | 与公告 5,040.7 百万对撞 |
| **折旧与摊销** | 亿元 | **亿美元** ❌ | 量级排除：若为人民币则该公司一年只折 38 亿元，与体量矛盾 |
| **资本支出** | 亿元 | **亿美元** ❌ | 84.03 亿美元 ↔ 公告"资本开支 81 亿美元" |

**共同点时**：公司管理层习惯用美元口径披露的两个指标（capex、D&A），
万得取的就是美元数，但 unit 仍按表头写"亿元"。

### 必修的三步校验法

1. **与已知一手数字对撞**：先拿一期公告/定期报告的确定数字，跟万得同一期比。
   对不上就先怀疑单位，而不是怀疑数据。
2. **量级自洽**：用该公司的经营特征做常识判断（营收、固定资产净额、EBITDA 能否互相约束）。
3. **双单位互算隐含汇率**（最干净的一招）：同一个指标分别用自然语言要求返回"亿美元"和
   "亿元人民币"两列，相除。落在 6.8~7.3（USDCNY）即确认单位无误，
   **且这个汇率可直接拿来当本项目后续美元↔人民币的换算锚**。

### 降级问法的小技巧

在 `question` 里显式写「分别以亿美元和亿元人民币两种单位返回，用于校验单位」，
工具会真的返回两列——这比事后猜单位可靠得多。

### 坑 2：名义"每日"序列可能是季末快照前向填充

要陆股通每日持股，返回的却是：数值只在 **6/30、9/30** 跳变，中间 60 余个交易日完全不变。
**这不是真实日频**。判别方法：拉一段日内序列看是否出现长时间 plateau + 季末阶跃。
→ 这类序列**只能读季末净变化**，不能做日频流量分析。
（对照：东财同一指标给出的是同一组季末值 → 可交叉验证"变化是真的"，但同样不提供日频。）

### 坑 3：同一指标不同分母，看起来像数据打架

- 陆股通占比：占**流通 A 股**（约 20 亿股）→ 3.19%；占**总股本**（80 亿股）→ 0.80%
- 股东户数：**A 股口径** 287,089 户 vs **A+H 口径** 296,744 户

**两个都对**，只是一方用总股本/含港股，另一方用流通 A 股。
遇到"两源不一致"先排分母，别急着记冲突。

### 坑 4：公告检索返回的是片段，不是全文

`get_company_announcements` 按相关性返回**文本片段**，**表格里的数值会被丢掉**
（例如业绩演示材料里的"月度产能/利用率"表只剩表头）。
→ 需要精确数值时必须读公告 pdf 原文；片段只适合定位"哪份公告里有"。
另：返回的 `url` 是 Wind 终端深链，外部打不开。

### 能力边界（实测）

| 有 | 没有 |
|---|---|
| 三大报表科目、财务比率、估值（PE/PB/PS 及分位） | 晶圆出货量 / 月产能 / 产能利用率 / ASP（属经营数据，非财务库） |
| 股本结构、前十大（流通）股东、机构/基金持股、股东户数 | 按制程节点拆分的收入或产能（**公司不披露 → 任何数据商都没有**） |
| 大宗交易（汇总 + 逐笔）、限售解禁时间表 | 筹码分布（成本分布） |
| 陆股通持股（季末口径） | 子公司营业收入/净利润（"被参控公司"只返回净资产，且数值疑为注册资本） |
| 公告与新闻文本检索 | 港股通 / 南向持股（本次未取到） |

**衍生结论**：**"某家公司不披露的东西，换数据商也拿不到"**。
遇到一个缺口时，先问"这个数在一手披露里存在吗"——
不存在就该改用代理变量或逐层扣减，而不是继续换数据源撞墙。

## ★ 坑四：上交所公告 PDF 被阿里云 WAF 拦，换 `big5.` 子域直通（2026-09-19 实测）

取上交所披露的公告 / 报告书 PDF 原文时，实测路径：

| 路径 | 结果 |
|---|---|
| `static.sse.com.cn/disclosure/listedinfo/announcement/c/new/YYYY-MM-DD/688xxx_YYYYMMDD_XXXX.pdf` | ❌ HTTP 200，但返回约 3.8KB **HTML**——内容是 `acw_sc__v2` cookie 混淆脚本（**阿里云 WAF 挑战页**） |
| `static.cninfo.com.cn/finalpage/...PDF` | ❌ HTTP 403 |
| 巨潮 `cninfo.com.cn/new/hisAnnouncement/query` | ❌ 返回 `totalRecordNum: 0`（沪市科创板要正确的 `column`/`plate` 组合）；`fulltextSearch/full` 需 Content-Length，裸 curl POST 报 411 |
| **`big5.sse.com.cn`（上交所繁体站，路径与文件名一字不改）** | ✅ **HTTP 200，`application/pdf`，完整下载** |

**要点：只换域名，路径不动。** big5 站未挂 WAF 挑战。

```bash
unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy   # 见坑二
curl -sL -m 300 -o out.pdf \
  "https://big5.sse.com.cn/disclosure/listedinfo/announcement/c/new/2026-05-22/688981_20260522_FD29.pdf" \
  -H "Referer: https://www.sse.com.cn/" \
  -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120.0 Safari/537.36"
head -c 8 out.pdf    # 必须 %PDF-1.x
file out.pdf
```

**先验魔术字节再解析**：若 `%{content_type}` 是 `text/html` 或首字节不是 `%PDF`，直接判定被拦，别浪费时间走解析流程。

**找 PDF 直链的办法**：先用 WebSearch 搜「公告全名 + 上交所 + pdf」，搜索结果常直接给出 `static.sse.com.cn` 的完整附件 URL，再把域名换成 `big5.` 即可下载。比逆向公告查询接口快得多。

## ★ 长文档 PDF 的高效读法：先建索引，再定页精读（pymupdf）

监管文件动辄 300+ 页、30 万字，**不要整本读**：

1. **一次性建索引**：`pymupdf.open()` → `page_count` / `get_toc()`（书签直接给章节页码，实测 329 页有 811 个书签）/ 逐页 `get_text()`，把页面文本列表存 JSON 反复复用。
2. **关键词页分布**：对每个关注词扫出命中页号列表，**先看分布再决定读哪页**。关键词的「**0 命中**」本身就是结论——实测某报告书「先进制程」「14纳米」「月产能」全文 0 命中，一句话证实了「该口径结构性不存在」，省掉整轮检索。
3. **上下文裁切检索**：把每页压成单行后按词取 ±120 字上下文，比整页 dump 省约 90% 上下文开销。
4. **按页精读 + 手工录入**：只对命中页做完整抽取，原文逐字录入后**再跑恒等式校验**（本次 19 项全过，其中 `ASP × 销量 = 收入` 偏差 0.0000%）。

**环境事实**：
- 本机 `pymupdf` 在默认 venv（`C:\Users\zyx32\.workbuddy\binaries\python\envs\default`）与 managed 3.13 均可用。
- `import fitz` 会打印 deprecation 警告，直接 `import pymupdf`。
- **中文 PDF 提取质量**：WPS 生成的监管文件提取干净、无乱码；但**数字与中文之间常带空格**（如「7 万片」「2025 年度」），做字符串匹配前先归一化 `re.sub(r"[ \t\u3000]+", "", page)`，否则会出现**假 0 命中**。

## ★ 从「转引」升级到「一手」的标准动作

自媒体/财经媒体转引监管文件的数字，**必须回到原文确权才算过铁律**。流程：

1. 拿到 PDF 原文 → 归档到 `资料/公告原文/`（保留底稿可复核）。
2. **逐项列表比对**：目标值 / 此前转引值 / 原文值 / 判定（一致 / 需修正 / 推翻）。实测 16 项核心数据转引准确率 100%，但有 2 处需修正：**文件签署日期**（媒体按受理日写，原文封面是另一天）与**口径**（「7 万片/月」是转引者自算，原文只给年产能）。
3. **同时记录「拿不到什么」**——原文里 0 命中的字段同样要入账，它把「数据缺失」升级为「结构性不可得」。
4. 跑机器校验（恒等式 + 分项加总），全过才标「一手确权」。

## ★ A+H 公司的「市值」有三个口径，差可达 3 倍以上（必须写明用哪个）

只要标的同时有 A 股和 H 股，**「总市值」这个词就有三个互相打架的算法**，混用会让 PE/PS 差出几倍。

| 口径 | 算法 | 谁在用 | 语义 |
|---|---|---|---|
| **A 股口径** | A 股股本 × A 股收盘 | **东财**各处「总市值」（尤其股东户数表） | 只有 A 股部分，**不含 H 股** |
| **分币种口径** | A 股本×A价 ＋ H 股本×H价×HKDCNY | **Wind「总市值1」** | 真实把公司**整体**买下来要花的钱 → **PE/PS 的正确分母** |
| **全 A 价口径** | 全公司股本（A+H）× **A 股价** | **Wind「总市值2」** | 「假设 H 股也按 A 价成交」→ 把 A/H 溢价打满，虚高 |

**实测（中芯国际 2026-09-18）**：3,107 亿 / 6,484 亿 / 10,446 亿 → **差 3.36 倍**；
对应 PE(TTM) **43.1× / 90.0× / 144.9×**。

### 三步判定某张表到底是什么口径（把结论钉死，别靠猜）

1. **反解**：`该表总市值 ÷ 该表总股本` = 每股价格。若恰好等于**当日 A 股收盘价** → 是 A 股口径。
2. **用多头对撞**：东财股东户数表给的「股本变动」金额应能对上已知增发（中芯北方新增 547,182,073 股，
   19.9956 亿 → 25.4674 亿，一步不差）。
3. **用 Wind 反证 PE**：自算 TTM 归母，用某个口径反算 PE，能对上 Wind 公布的 `市盈率(TTM)` →
   那个口径就是 Wind 在用的。实测：自算归母 72.07 亿，全 A 价口径反算 144.937× vs Wind 144.936× → **坐实**。

### 记死的搭配规则

- **PE / PS（公司整体估值）→ 只能用「分币种口径」。**
- **融资余额 ÷ 市值（杠杆）→ 分子是 A 股融资盘，分母必须同为 A 股口径**（用错会被低估到 1/2）。
- 任何引用 PE/PS 的地方，**必须带着口径标签**，否则等于没写。

### 自检要写进脚本（每次重跑自动验）

```python
# 对窗口内每一期，核实「东财总市值 == A股本 × A股当日收盘」
ratio = 表里的总市值 / (总股本 * 当日A股收盘)
assert abs(ratio - 1) <= 0.005   # 实测 10/10 期 = 1.0000，0 偏离
```
比值不恒等于 1 → **取列错位了**，先修脚本再看结论。
