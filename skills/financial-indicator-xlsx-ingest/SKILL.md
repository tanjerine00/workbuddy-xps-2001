# 财务指标域：投喂 → 校验 → 派生 → 入体系

## 何时用

- 用户给券商/东财妙想/万得终端导出的**财务指标类**文件（盈利能力与收益质量、资本结构与偿债能力、每股指标、成长能力、现金流指标、营运能力…），说「投喂」「继续投喂，完善起来」「接到系统里」。
- 要把一批**比率型指标**变成长时间序列（年度 / 半年 / 单季），或要拿它去对撞已有主表。
- 要先读 `broker-target-price-tracking`（同类思路，管的是一手事件类 CSV）——两者的**纪律一致、解析对象不同**：那边是自然语言列，这边是两层表头。

## 铁律（先立规矩再动手）

1. **素材投喂 → 交叉验证 → 写入**。自动链**永不代改**任何 CSV 数值；入库是**手工入口**，校验与派生才入自动链。
2. **两份落盘**：`*_<域>.csv`（规范域：报告期 × 指标，供计算）+ `*_原样.csv`（保留源表布局，供审计复现，**不参与任何计算**）。
3. **进结论的数字至少两源**。重叠指标必须跨源对撞；容差只用于判「一致与否」，**禁止取平均/插值/平滑**。
4. **查不到就写「查不到」**，绝不用估算填补。**不做数值补全**。
5. **口径差异如实并列**：同名不同义的列（扣非口径、ROE 摊薄/加权/平均、资产负债率直报 vs 反推）**不判谁对**，并列记录。

## 步骤

### 1. 先画像，再写解析器
用 `openpyxl` 打开，**逐格读**看清楚：表头几层、合并单元格范围、分组行文本形态、期间列是哪个区间、单位行在哪、有无「来源」注脚行。

**★ 坑 1：两层表头的分组行是纯文字。** 源文件往往是
```
A1: (空)  B1: 盈利能力        C1: 收益质量
A2: 报告期 B2: 毛利率   ...
```
分组行**不是** `【盈利能力】` 这种带括号形态；含「来源」「注」的行必须跳过。先打印前 6 行原样再动手。

**★ 坑 2：`ReadOnlyWorksheet` 没有 `.dimensions`。** 用
```python
try:
    dims = ws.calculate_dimension()
except Exception:
    dims = None
```
不要直接取 `.dimensions` 属性（会 AttributeError）。

**★ 坑 3：读原始精度，不读显示值。** 用 `cell.value`（float），不要用带格式的字符串——否则 0.0001 级差异被四舍五入掉，跨源对撞会失真。

### 2. 写元数据（可复现的最小集）
`_<域>_元数据.json` 至少含：**源文件 sha256**、行列数、每列原始精度、分组结构、入库时间、脚本名。
> sha256 是「日后能证明这批数确实来自这份文件」的唯一手段。

### 3. 写校验脚本（分「阻塞项」与「记录项」）
把校验项编号化（如 `I-01…I-14`），并且**明确区分三类**：

| 类型 | 判据 | 是否 `exit 1` |
|---|---|---|
| A/B 类（结构、覆盖、转置零差异） | 必须全过 | **是**（阻塞） |
| 记录项（口径差异、舍入差） | 只记录并解释 | 否 |
| **稀疏列登记** | 源端本就只部分期间产出 | 否 |

**★ 坑 4：别把「源端稀疏」判成「有缺口」。** 会计比率里大量列只在年报+中报产出。
→ 裁决：**域整齐可入册**，但稀疏列**只做同口径点对点比较，禁画趋势线、禁插值、禁前值填充**。
把每一项稀疏列逐个登记（哪几期有、哪几期没有），写进口径文档。

**★ 坑 5：转置零差异是必测项。** 规范域 ↔ 原样域互转后逐格对撞，应当 **0 差异**；不为 0 说明解析器有损。

### 4. 跨源对撞（重叠指标）
拿新域与已有主表重叠的指标（毛利率、净利率、研发费用率…）逐期对撞，记 `maxΔ`。
本项目实测：23 期重叠，`maxΔ ≤ 0.0050 pp` → 两源印证。
**容差只判一致性**（如 TOL=0.02），**不为对齐而放宽容差**——发现不一致以重算值为准并去查根因。

### 5. ★ 反解式钉死「分母口径」（最容易翻车的一步）
比率类指标总有一个「股权价值 / 全部投入资本 / 净资产」分母，**这个分母是哪个口径的市值/权益，源文件不会告诉你**。

打法：**挑一期，用该期多个比率联立反解**，再与「自算值」和「第三方核证值」双向对撞：

```
反解分母 = 分子 / 比率        # 用 2~3 个不同比率各反解一次
自算分母 = 按不同口径各算一遍（A股口径 / 分币种口径 / 全A价口径）
核证分母 = 第三方（万得等）公布的归母权益
→ 只有一种口径能同时匹配反解值与核证值 ⇒ 钉死它
```

本项目实测（**24 期全量**，即该两列在源端有值的全部期间）：

| 证据 | 覆盖 | 结果 |
|---|---|---|
| ① 权益链（不依赖股价/股本/汇率） | 24 期 | 反解权益 vs 第三方核证：**max 0.0130%／中位 0.0059%** |
| ② 外部市值锚（第三方**历史时点**总市值） | 24 期 | **23 期 ≤0.045%**，且 **24/24 期只有「分币种口径」更接近** |
| ③ 本地行情独立自算三口径 | 10 期 | **分币种 max 0.043%**；另两口径 −48~−61% / +55~+107% |

三口径中**只有分币种口径匹配** ⇒ 钉死为 **A+H 分币种口径**。

**★ 节奏铁律：一期不算证据 → 先做两期（必须跨不同股本结构）→ 能做全量就做全量。**
- 两期的意义：本项目两期总股本差 **7.0%**（期间 A 股完成发行融资 5.47 亿股）；
  **同一个口径在股本变动前后都对得上，才排除巧合**。只做一期时，反解值与自算值可能"刚好"对上。
- **全量的意义**：做全量时往往发现「上轮以为只有 2 期能做」**是判断错，不是数据不够**——
  先去**数**「该比率列到底有几期非空」，别凭印象。本项目实测该两列有 **24 期**（不是 2 期，
  也不是我上一轮写的「仅年报+中报」——那是把 EBITDA 类稀疏列的性质错套到了股权价值列上）。

**★ 关键手法：第三方**历史时点**市值是最好用的外部锚。**
本地行情/汇率常受「时间口径铁律」限制（本项目本地数据自 2024-01-01 起），
但第三方接口（如万得 `get_stock_fundamentals` 问「YYYY-MM-DD 的总市值1 / 总市值2」）**能返回历史时点值**，
且**一次可批量带 8 个日期** → 于是 **2020 年的期也有人对撞**，不必依赖本地推导。
→ 这条锚还顺带消掉「期末日非交易日」的歧义（第三方自己按最后交易日取价）。

**★ 分母口径钉死后，还要钉股本口径（最容易漏的一步）**：同一数据商的「总股本」可能有**多个字段且互不相等**。
本项目实测：`00981.HK 总股本` = 85.62264585 亿、`688981.SH 总股本` = 85.60805995 亿，**差 0.0170%**；
该源的 BPS / 归母权益 / 所有者权益合计都按后者算。
→ 用法：**引用市值口径用「能与第三方公布 PE 复现」的那个值**；**逐期股本换算用「与该源权益自洽」的那个值**。
→ 这 0.017% **不影响口径判定**（判定要区分 2 倍以上），但**不能解释成「舍入」**——
  旧文档里凡写「偏差很小，属舍入」的地方，都应回头查一次是不是字段差。

**★ 用一条跨源恒等式检验股本字段选得对不对。**
本项目：`东财 BPS × 万得总股本 ?= 万得归母权益` —— 24 期中 **22 期精确成立**（≤0.0003%＝BPS 四位小数舍入上界），
且**证伪**了「全域回乘同一个股本」的用法（最大偏差将达 **9.04%**）。
剩下 2 期例外（2020 年，正值 A 股 IPO + 绿鞋登记期）**如实并列、不判定谁对、不取平均** → 登记为「记录项」。

**★ 一定会有离群期，处理方式是「登记」而不是「解释」或「删掉」。**
本项目 24 期里有 1 期偏差 **+0.66%**（其余 max 0.0445%，差 15 倍）。
候选线索（该期末兼有股本变动 + 节假日休市 → 「双重边界日」）**只写【推测】、不采信**；
校验脚本对该期**单列一个更宽的阈值**（0.70% vs 其余 0.10%），使它**既不被静默吞掉、也不阻塞重跑链**。

**钉死后必须写进三处**：计算口径台账（该指标备注）+ 记忆的「一引用就错的口径」清单 +
一份**可自动重跑的复核报告**（本项目为 `_财务指标派生.md` §六），并写明**覆盖到哪几期**
（本项目：该两列的全部 **24 个非空期**；2020Q1 / 2020 中报源端即无该列，非遗漏）。

**★ 外部锚要落成数据资产，不要硬编码在脚本里。**
写 `.workbuddy/ingest_<锚>.py` 生成 `数据/.../<锚>.csv`（本项目 24 行），入库脚本里做：
① 结构自检（期数、重复、`归母权益 < 所有者权益合计`、`总市值1 < 总市值2`）；
② **单位归一**（见坑 11）；③ 派生脚本与校验脚本**都读这一份**，防两处漂移。

### 6. 派生脚本
年度序列 / 半年序列 / 最新期在窗口内的**位置分位** / 关键变化 / 口径验证节。
分位要写清是**窗口内分位**（26 期），不是「历史分位」。

### 7. 体系同步（四处，缺一不可）
- `体系/run_all.py`：把校验脚本与派生脚本插入重跑链；**同步注释里的步数**（易忘）。
- `体系/素材台账.md`：给本次投喂登记一个新编号。
- `体系/计算口径台账.md`：把新能算的项按 T1/T2/T3 加进去，**每条都写清分母口径与坑**。
- `体系/时间口径铁律.md`：若出现「稀疏列」这类新裁决，写成 §补 条款。
- 展示层（如 `系统数据.js`）：加项、加材料条目、加结论；`meta.version` / `builtAt` 同步。

## 通用陷阱（跨项目复用）

**★ 坑 6：编号撞车——编号必须在唯一权威源登记。**
展示层（`系统数据.js`）里可能**先占了号但没入台账**。新域直接取「下一个号」就会静默撞车。
→ 新增编号前**两个文件都 grep 一遍**；发现撞车就全量改号 + 把被撞的那条补登台账，使两边一致。

**★ 坑 7：断言器不要依赖数组下标。**
`S.rules[0] / S.rules[1]` 这类固定下标断言，在**追加式增长**的结构上（规则从 8 条长到 9 条、顺位变动）会**静默失效**——
测试一直红却没人发现。改为**全表检索**：
```js
const all = (S.rules || []).map(r => (r.t || '') + ' ' + (r.d || '')).join('\n');
ok('存在「零缺口」规则', /零缺口/.test(all));
ok('规则条数 = 9', (S.rules || []).length === 9);
ok('每条规则都有 t 与 d', (S.rules || []).every(r => r.t && r.d));
```

**★ 坑 8：用 shell 内联 / heredoc 写内容，会「报错」也会「静默吃字符」。**
两种失败模式本项目都踩过：
- `python - <<'EOF'` 往 `.js` 写 `join('\n')`：shell 层先把 `\n` 解成真换行 → 生成裸换行 → `SyntaxError`（**会报错，还好**）。
- `python -c "…反引号…"`：双引号内的反引号被 shell 当**命令替换**，命令不存在就**替换成空串** →
  内容被**静默吞掉**。本轮实测往 `.md` 追加的段落里 4 处（`股权价值` / `总市值1` / `锚Δ` / `%.2f` 的反引号形式）
  **凭空消失，脚本却照样打印「写入成功」**。**不报错的这种最危险。**
→ 含反引号 / 中文 / 转义序列的内容**一律走 Write/Edit 工具**，或**先落盘成 `.py` 再执行**；
→ 修复脚本自身也要防复发：用 `chr(96)` 拼反引号，或直接走 Edit 工具；
→ 写完后**回读并断言关键子串仍在**（本轮就是靠回读复核才发现的）。

**★ 坑 9：反向复算闸门的负测试，锚点本身要先验唯一性。**
给「独立重算 × 对撞已写下的数」这类闸门做负测试时（篡改报告里一个值，确认闸门会变红），
**替换用的锚点常常不唯一**——同一个数会在正文表、对照表、结论句里各出现一次。
本项目实测：想把 6328.0 改成错值，结果 §6.1 与 §6.2 两张表都有该值，脚本自己先报「锚点不唯一」。
→ 负测试脚本必须**先断言锚点命中数 == 1**，不唯一就中止（**不要"改第一个"**）；
→ 并且**还原后比对本文件字节一致**，否则负测试本身会污染数据。

**★ 坑 10：「计数 / 步数 / 条目清单」类信息只保留一个权威源。**
本项目为了让校验项 14→16，同一个数字散落在 **5 个文件**里，只能写成一次性幂等补丁才没漏
——而第一版补丁**仍然漏了记忆卡里的一处**，是后来精简时才对出来。
→ 凡计数、步数、条目清单，**只在唯一权威源里枚举**（脚本顶部 docstring / 工具输出），
  其他位置一律**引用而不复述**（写「完整清单见 XX」，不要抄一遍）。
→ 同理，**记忆/索引卡里不要枚举步骤清单**——那是一份必然会过期的复制品。

**★ 坑 11：第三方 `unit` 字段会「跳档」。**
万得的 `unit` 字段不可信（本项目另一例：「折旧与摊销」标"亿元"实为**亿美元**）。
本轮实测：历史 `总市值2` 在相邻期里突然标成 **「万亿元」**（值 `1.1209` = **11209 亿**），前后期却是「亿元」。
→ 入库脚本必须**逐列量级校验**（如 `总市值2 ÷ 总市值1` 应落在 1.3~2.5× 的稳定带内；跳档即报错退出）；
→ 换算**写在入库脚本里留痕**，不要在别处悄悄处理。

**★ 坑 12：校验阈值必须由「源端精度」反推，不能拍。**
本轮新加的闸门**第一次跑就判红**，看着像数据缺陷，实际是我把阈值（0.0005 亿）设得**比源端精度还紧**——
报告里的总市值按 `%.2f` 书写，本身就有 0.005 亿的舍入。
→ 正确做法：**先算源端精度给出的理论上界**（源端比率只给 2 位小数 ⇒ 市值偏差上界约 0.05%），
  取其 **2 倍**作阈（0.10%），并把**依据写进代码注释**。
→ 更重要的推论：**「闸门红了」的第一反应应当是「阈值对不对」，而不是「放宽阈值」**——
  后者正是「放宽容差迁就错数」的开端。
→ 顺序永远是：**先确认基线是绿的**（如果不是绿的，先查基线）→ 再做负测试（篡改一处，确认真的变红）→
  负测试**锚点必须先断言唯一**、**还原后比对本文件字节一致**（见坑 9）。

## 边界（明确不做）

- 稀疏列**不做趋势线 / 插值 / 前值填充**。
- 跨源冲突**如实并列**，不取平均、不挑对自己有利的。
- 不为「有缺口的域」找回数据——**缺一期即下架归档**（零缺口原则）。
- 不用第三方现成读数冒充自算。
