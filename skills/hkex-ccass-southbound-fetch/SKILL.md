# 港交所 CCASS + 港股通南向持股：抓取与双源核证

## 一句话结论

**这两条通道都通，但各有一个人造的「假失败」陷阱**：港交所缺 `today` 字段会静默返回搜索页（看着像被封），
东财不去重会把样本量吹成两倍。**核证的关键动作不是抓数据，是做「分母反推」**——用已核证的股本反算 `股数÷占比`，
一次同时验出「数字真伪」和「口径是什么」。

---

## 一、通道①：港交所 CCASS 席位级持股

```
https://www3.hkexnews.hk/sdw/search/searchsdw.aspx
```

### 1.1 ★ 唯一必须记住的坑

**`btnSearch` 是 `<a>` LinkButton，不是 submit** → 必须走 `__doPostBack('btnSearch','')`。
但**真正让人误判的是隐藏字段 `today`**：

| 字段 | 值 | 后果 |
|---|---|---|
| `__EVENTTARGET` | `btnSearch` | 不带 → 不触发 |
| `today` | **`yyyymmdd`（如 `20260920`）** | **写成 `2026/09/20` → HTTP 200 + 返回搜索页本身、零结果、零报错** |
| `__VIEWSTATE` | 从 GET 页取 | 不带 → 可能拒绝 |
| `txtShareholdingDate` | `YYYY/MM/DD`（**斜杠格式**） | 这是查询日，格式与 `today` **不同** |

> ⚠ `today` 是 `yyyymmdd`、`txtShareholdingDate` 是 `yyyy/mm/dd` —— **同一页两种日期格式**，是主要出错点。

**失败模式辨析**（重要）：搜索页内**内嵌了 Terms of Use 弹窗文字**，所以「拿到一页带条款文字的页面」
很容易被解释成「港交所要求先接受条款」。**实测不是**——那只是搜索页本身。**判断真失败的唯一标准：
返回页里有没有 `search-details-table-container` / `ccass-search-total`。**

### 1.2 正确流程

```python
# 1) GET 拿 __VIEWSTATE + cookie（bm_s / bm_so）
# 2) 把 GET 页里所有 <input> 的 name/value 照抄进字典（别手写字段名！）
#    —— 这样 today / __VIEWSTATEGENERATOR / originalShareholdingDate 自动带上
# 3) 覆盖：__EVENTTARGET=btnSearch, __EVENTARGUMENT="",
#          today=datetime.date.today().strftime("%Y%m%d"),
#          txtStockCode=<code>, txtShareholdingDate=<YYYY/MM/DD>,
#          sortBy=shareholding, sortDirection=desc
# 4) POST，Content-Type: application/x-www-form-urlencoded，带 Referer/Origin
```

**★ 心法：从 GET 页照抄全部 input，而不是凭记忆拼字段。** 港交社会加我们不知道的隐藏字段，
漏掉的后果是「静默 no-op」而不是报错——这种错最难查。

### 1.3 解析

| 位置 | 作用 |
|---|---|
| `summary-category">NAME<` 起向后 1200 字符内的 3 个 `<div class="value">` | 汇总行（股数 / 家数 / 百分比） |
| `Total number of Issued Shares/Warrants/Units` 后的 `summary-value` | **港交所口径已发行股份**（所有百分比的分母） |
| `<tbody>` 内每 `<tr>` 的 5 个 `<td>` | 明细 |

**★ 每个 `<td>` 里有两层**：
```html
<td><div class="mobile-list-heading">Shareholding:</div>
    <div class="mobile-list-body">1,446,903,832</div></td>
```
**只取 `mobile-list-body`**，否则标签文字会被拼进数值 → 解析看似成功其实全是脏数据（我第一次就这样）。

### 1.4 自检口径（别自己骗自己）

明细表**只含 Market Intermediaries + Consenting Investor Participants**，
**不含 Non-consenting** → 用「明细合计 vs Total」自检必然不等（会白查半天）。

```
正确基准：明细合计  ==  MI 股数 + 合资格股数
```

## 二、通道②：港股通南向持股逐日序列

```python
# 东财（明文 HTTP + 必须去掉代理）
http://datacenter-web.eastmoney.com/api/data/v1/get
  ?reportName=RPT_MUTUAL_STOCK_HOLDRANKS
  &columns=ALL&pageSize=500&pageNumber=N
  &sortColumns=HOLD_DATE&sortTypes=-1
  &filter=(SECURITY_CODE="00981")
```

### 2.1 ★ 两个必改的地方

1. **`MUTUAL_TYPE` 002 与 004 是同值重复行**（沪/深港通各报一条，数值完全相同）
   → **必须按日期去重**，否则样本量正好翻一倍（944 → 472）。
2. **分页数必须用抓取时的 `pageSize` 去算**。用 `pageSize=1` 探到 `pages=189` 再按 500 条/页翻
   → 白跑 188 次空请求、并可能直接超时被杀。

### 2.2 字段口径

| 字段 | 含义 |
|---|---|
| `HOLD_SHARES` | 南向持股股数（**与港交所 CSDC 席位合计逐位一致**） |
| `HOLD_MARKET_CAP` | 港币市值 |
| `HOLD_SHARES_CHANGE` | 当日变动股数 |
| **`HOLD_SHARES_RATIO`** | ⚠ **占总股本**口径，**不是**占 H 股口径 |

**滚动两年**：接口只保留最近两年 → 起点会「漂移」。**别把起点当成数据边界**，必须实测并如实登记缺口。

## 三、★ 核证三件套（这一步才是价值所在）

### 3.1 分母反推（零成本、抓错能力最强）

拿项目内**已核证的股本**反算 `股数 ÷ 该数字公布的百分比`，看落在哪个分母上：

```
中芯 6.15亿 ÷ 7.18% = 85.66亿  → 总股本口径（8,560,677,950 ≈ 85.61亿）✅
中芯 24.59亿 ÷ 40.89% = 60.14亿 → H 股口径（6,014,430,432）           ✅
```

**一次同时验出两件事**：数字是真的，且百分比用的哪个分母。
**若反推不出任何已知股本 → 该数字不予采用。**

### 3.2 同实体多席位（最容易被漏掉）

**港股通在 CCASS 里同时占用 `A00003` 与 `A00004`，名称都叫 `CHINA SECURITIES DEPOSITORY AND CLEARING`。**
→ **必须按名称聚合、不能只看首行**。

真实后果：只看券商席位会得出「中银国际居首」——**错**，它排第 3；前两名是 CSDC 两个席位，
合计占已发行 28.73%。**「谁最大」这种结论，一旦漏席位就会全错。**

### 3.3 双源对撞

| 源 | 取法 |
|---|---|
| 源① 港交所 CCASS | 把**所有** CSDC 席位的 `mobile-list-body` 股数相加 |
| 源② 东财 | `HOLD_SHARES`（已去重） |

**两者应逐位相等**。中芯 2,459,373,110 / 华虹 302,036,819 —— **零偏差**。

## 五、★ 方法论红线：CCASS 不能用来归因「国家队」

**CCASS 是席位级，不是受益人级。** 一个券商席位 = 该券商**全部客户**的合计。
且战略股东以「境外上市外资股」登记，**不出现在席位名上**
（中芯：大唐香港 1,125,042,563 股、鑫芯香港 382,902,023 股）。

→ **不得用「某券商席位变动」推断国家队进出。**
要答「国家队」只能走**定期报告前十大股东 / 十大流通股东**。
CCASS 的正确用途是：**南向资金流向** + **券商层面的托管分布变化**。

## 六、限流与稳健性

- 连续请求间隔 **≥ 3 秒**（实测 4 秒稳定）。
- 港交所 CCASS **只保留过去 12 个月**，但**支持按历史日期查询**（实测 `2025/12/15` ✅、`2026/03/10` ✅、`2025/09/18` ❌）
  → **12 个月内的逐日序列是可以做出来的**（本轮做出 237 个交易日）；超过 12 个月的**永久不可得**。
- 任何"百分比"引用必须写：**分母（H 股 / 总股本）+ 数据日 + 来源**。

## 六点五、★ 通道③（北向）：港交所官方「沪深股通持股录」

`https://www3.hkexnews.hk/sdw/search/mutualmarket.aspx?t=sh`

**★ 这是北向，不是南向（极易误判）**：页面含 **2043 只 A 股**、标签 `Northbound` / `Shanghai Connect`；
港股代码不在列表里（`00981` 只会作为 `600981` 的子串出现）。同一 WebForms 套路
（`__EVENTTARGET=btnSearch` + 隐藏字段 `today=yyyymmdd`）。

### 三条与 CCASS 不同的口径

1. **返回的是季末，不是当日**：默认 `originalShareholdingDate` = 今天，
   但实际 `txtShareholdingDate` 回落到**最近已公布的季末**。
2. **请求日 ≠ 返回日**：请求 `2026/06/30` → 返回 `2026/03/31`
   （上季度末数据要到**下一季度第 5 个沪深股通交易日**才公布）。
   → **必须读页面回显的 `txtShareholdingDate`，绝不信请求参数。**
3. **保留期同样约 12 个月**：`2025/09/30` 可查；`2024/12/31` 及更早 → 空表。

### ★★ 最会骗人的坑

超期时页面**不报错、不回退日期**，只给一张空表（`<tr>` 只剩 4 行）。
**判断「有没有数据」必须校验行数，不能只看 HTTP 200 或回显参数。**

**可用价值**：北向持股的**官方季末口径**，可给付费/三方源的季度序列做对撞
（本项目实测：与万得 **4/4 逐位一致**）。

## 六点七、★★ 东财机构明细的重复行陷阱

`RPT_MUTUAL_HOLDNDATE_DET` / `RPT_MUTUAL_HOLD_DET` 对**同一席位**会按
`INTERVAL_TYPE` = **1 / 3 / 5 / 10** 各返回一行（**同值**）。
**直接按席位求和会得到 4 倍**——本项目首次实测就把南向算成 98.4 亿股（总股本才 85.6 亿）。
→ **必须按 `INTERVAL_TYPE=1` 去重**，去重后 `A00003` + `A00004` = 24.59 亿 ✅。

## 六点八、★ 制度性事实：北向日频持股已终止（别当成「没找到」）

- **2024-05-13 起**：北向**实时净买入金额**停披露；
- **2024-08-19 起**：北向**单只证券的托管机构持仓数量停止按日披露**；
  「中央结算系统持股纪录查询服务」与「沪深港通持股纪录查询服务」

→ **北向日频持股永久不可得。这不是数据源问题，换源也解决不了。**

## 八、★ 南向持股「从今天起零缺口」重建（2026-09-22 实测，完整跑法）

**背景**：源恒保留**滚动 2 年** ⇒ 起点每天前移。若每次覆盖落盘，序列会**越来越短**；
若要「覆盖 2024-01-01 起」（铁律起点），源给不到前 177 个交易日 → 按零缺口原则只能下架。
用户 2026-09-22 拍板改为「**从今天起零缺口**」——这是**域级例外**，不是放宽铁律。

### 8.1 两条机制（缺一不可）

1. **冻结基座**：把首次抓取时源端能给的最早一天钉为起点（实测 **2024-09-23**），
   并**写进文件名**（`00981_南向持股_自2024-09-23_日频.csv`）→ **起点前移必然改名，无法静默发生**。
2. **合并模式**：抓取时读现有 CSV、与本次结果**取并集**（不是覆盖）。
   ⇒ 源把 2024-09-23 挤出窗口后，本地仍保留它，序列**随时间单调生长**（今天 472 天，一年后约 716 天）。

> ⚠ 若只做「每日抓最新」而不合并 —— 起点会漂，历史被自己吃掉。**这是本域最反直觉的坑。**

### 8.2 零缺口怎么证明（★ 不能用港股日历）

理想日历 = **A 股市场交易日 ∩ 港股交易日**（= 港股通交易日）。
- **A 股日历必须补上「本股停牌日」**：中芯 2025-09-01~09-08 停牌 6 天，占位行已从日线剔除，
  但那 6 天**内地市场是开市的** → 不补就误判成休市（**首次实测即差 7 天**）。
- 对撞结果：南向 472 天 = 理想集 471 天 + 1 天（2026-09-21，日线源未更新）⇒ **缺失 0 天** ✅。
- **对照**：只用港股日历会造出 **19 天「假缺口」**，逐日核对全为 A 股休市日（内地节假日）。

### 8.3 双源对撞的两处修正（与本文前半不同，以本节为准）

1. **CCASS 明细必须按 `class` 取数，不能按位置**。真实列序是
   `col-participant-id / col-participant-name / col-address / col-shareholding / col-shareholding-percent`
   —— 按位置取会把 `A00003` 当股数（`num()` 剥出 `3`）。**首跑即中此坑。**
   （正则注意：`col-shareholding` 是 `col-shareholding-percent` 的前缀，判定顺序要把 percent 放前面。）
2. **汇总自检有 31 股固有差**：港交所汇总 MI **381 家 / 5,997,809,935**，明细只列 **380 行 / 5,997,809,904**
   （且合资格 2 家 26,000 股不在明细）⇒ 自检差 **26,031 股（0.0004%）**。**如实登记，不修正**；
   **不影响对撞**（CSDC 两席位都在明细顶部，合计仍逐位相等）。

### 8.4 ★ 新口径坑：`HOLD_SHARES_RATIO` 的分母**不固定**

`ratio_total_pct` 用的是**当期总股本**：反解 2024-09 ≈ **79.75 亿** → 2026-09 ≈ **85.67 亿**
（A 股在此期间增发）⇒ **跨期比较该比率会混淆「南向增持」与「股本扩张」**；
看资金进出请用**股数**，或自算 `股数 ÷ H 股本`（落盘宜加派生列 `ratio_h_pct`；H 股本用项目已核证固定值）。

### 8.5 落盘与接线

- `fetch_south.py`（抓取：去重 002/004 + **合并模式** + 源内连续性自检 + 派生 `ratio_h_pct`）

### 8.6 顺手记下的 Python 坑（本次连犯两次）

`%,d` **不是合法的 `%` 格式**（`%` 格式化不支持千分位）→ 千分位必须用 `"{:,}".format(x)` 或 f-string `{x:,}`。
`ValueError: unsupported format character ','` 就是它。
