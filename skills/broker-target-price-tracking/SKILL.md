# 券商目标价：核验入库 + 持续监控

## 何时用

- 用户给一份「券商评级与目标价跟踪」的 md / xlsx / csv，说「投喂」「核实并订正」「作为数据基座收入系统」「往后持续监控」。
- 要给一只 A+H 两地上市标的建卖方预期跟踪（目标价分布 / 分歧 / 隐含 A/H 溢价）。
- 要把「最新目标价」变成能定期自动刷新的读数。

## 铁律（先立规矩再动手）

1. **不删行留档**：核实不足的行不删，加 `usable` 标志位，**所有派生与结论只取 `usable=1`**。用户原话「核实不了的不取」不等于「从表里删掉」。
2. **A/H 分文件、分统计**。两地价格不同、投资者结构不同、往往连分析师都不是同一批人。混算中位＝把两个不同样本强行平均。
3. **基座只能由「投喂 → 核验 → 订正」更新**；自动链（抓取/派生/自检）**永不代改基座数值**。
4. **事件类数据的「完备性」不可自证**：没有「全部研报」的权威清单 → 「共有 N 家机构覆盖」这类**计数结论一律禁止**，只允许分布/分歧类读数。
5. **两个源概念不同时，差异如实并列，禁止取平均**（综合值＝各家加权，中位＝等权中位；差异本身就是信息）。

## 步骤

### 1. 先画像，再写解析器

**不要**直接按你猜的格式写正则。先跑一个只做统计的脚本，把每列的**形态模板**打出来：

```python
pat = {}
for r in rows:
    t = re.sub(r"[0-9]+(\.[0-9]+)?", "#", (r[col] or "").strip())
    pat.setdefault(t, []).append(r[col])
for t, vs in sorted(pat.items(), key=lambda x: -len(x[1])):
    print("%4d  %-34s  样例：%s" % (len(vs), t, vs[0][:60]))
```

这一步能直接把「没想到的写法」暴露出来（实测抓到 `75.78-86.61 港元` 区间式、`20.00 港币` 币种异写、`118.88%` 只给百分数、`无`/`—`/`无目标价` 三种空值写法）。

### 2. 解析的两个必修坑（都真实踩过，会静默算错）

**坑 A：叙述句里的数字是「新目标价本身」，不是变化额。**
`H股目标价下调至22.2港元(前值未披露)` —— 22.2 会被抓成「变化额」。
→ **变化额一律 `tp − tp_prev` 自算**；原文若给 `±X元/港元` 只用于**交叉校验**（本项目实测 119 条可比、全部自洽）。

**坑 B：括号里的内容会污染解析。**
`29.2 港元(8-10月间上调)` —— 区间正则会把 `8-10` 当目标价区间，解析成中值 **9.0**（真值 29.2）。
→ **先剥括号再解析数值**：`re.sub(r"（[^）]*）|\([^)]*\)", "", s)`。

**坑 B 的镜像坑（更隐蔽）**：如果你要从括号里取「自述百分比」`(+9.6%)`，
就必须**在剥括号之前**取，否则永远取不到 → 校验项会「0 条可比、0 条不符」**假通过**。
正确做法：原串取百分比、剥括号串取金额，两条路各走各的。

### 3. 机械校验清单（12 项，全部可自动化）

单条「已核实」是采集方自述，能被独立验证的只有内部自洽与外部对撞：

| 项 | 检查 |
|---|---|
| 1 | 市场可判定（不能留「—」，否则 A/H 分不了） |
| 2 | 日期全部可解析、起点不早于项目铁律起点 |
| 3 | **目标价币种与市场匹配**（A→人民币 / H→港元） |
| 4 | **变化额自洽**：原文自述 vs `tp − tp_prev` |
| 5 | **变化率自洽**：原文自述 % vs 自算 % |
| 6 | 无重复行（日期+机构+市场+目标价） |
| 7 | 核实状态可判定 → `usable` 标志位自洽 |
| 8 | **目标价量级**：对照当日收盘，落在 [0.3x, 4.0x]（抓单位错、抓小数点错） |
| 9 | 落盘后**排序**（用户常指定「按机构及时间」） |
| 10 | **与上一版对撞**：重合键上目标价是否被改动（键用 日期+机构+**币种**，因为旧版的 market 列常有空） |
| 11 | 新增/删除清单（说明「订正」到底改了什么） |
| 12 | **表头列数 == 每行字段数**（防「表头错位」：源 CSV 表头少列而数据多字段时，按名取列会整体右移一位，静默算错） |

### 4. 落盘成基座（A/H 分文件）

```
数据/{代码}_目标价与评级_A股_{起}_{止}.csv
数据/{港股目录}/{代码}_目标价与评级_H股_{起}_{止}.csv
```

文件名里嵌**真实**起止日期（源件自述的区间经常与实测不符）。
列至少包含：`date, broker, market, rating, rating_prev, tp, tp_currency, tp_prev,
chg_amt, chg_amt_src, chg_pct_stated, chg_pct_calc, tp_action, tp_is_range,
verify_status, usable, flags, src_claim`。
`src_claim` 保留来源原文——这不是冗余，是把「可回溯」落到列上。

★ 落盘后**必须再跑一次独立校验**：不复用入库脚本的任何函数，用另一条路径重算中位数，
去对撞派生报告里印出来的数字（容差 0.5%）。只靠入库脚本自检会「两端错得一致」。

### 5. 持续监控（两个源，性质完全不同）

| 源 | 给什么 | 怎么取 | 限制 |
|---|---|---|---|
| 东方财富研报接口 | **事件**：机构/日期/评级/偶有目标价 | HTTP 可脚本化：`reportapi.eastmoney.com/report/list?pageSize=100&pageNo=1&beginTime=&endTime=&qType=0&code=688981` | 目标价字段 `indvAimPriceT` 覆盖率极低（实测 3/34）；**H 股 0 条** |
| 同花顺 iFinD | **日频一致预期**：`目标价(综合值)` | MCP `get_security_indicators`，market 填「A股」/「港股」，query 写「<标的> 最新目标价(综合值)」 | 只回溯 **365 天**；是加权综合值，非逐家 |

架构纪律：
- 脚本（HTTP）负责事件增量，落**候选区**，**绝不直接写进基座**；
- agent（MCP）取一致预期，注入 `*_目标价一致预期_*.csv` 逐日追加；
- 两源对照：综合值 vs 基座窗口中位，**≤10% 视为互相印证，>20% 须查口径**；
- 报告里输出「基座最后一条研报距今天 N 天」，超 21 天告警 —— 数据静默过期是最容易骗过自己的失效模式；
- 定时任务里写死硬约束：「绝不改写基座 CSV」。

### 6. 展示层（若挂到 HTML 报告）

- 由派生脚本**自动生成**一个独立数据 JS（`window.SYS_SELL = {...}`），数值零手抄，别并入手写维护的主数据文件（重跑会冲掉人工文案）。
- A/H 用**子标签切换**（`A股 / H股 / A/H 对照`）而不是上下堆叠——用户要的就是「分开」。
- ★ **整段脚本若包在 IIFE 里，内联 `onclick="fn()"` 找不到函数**（`"use strict"` 下函数不在 window 上）。
  修法：显式 `window.__fn = fn;`，onclick 里写 `window.__fn(...)`。
- 验收用无头浏览器（本机用 Edge：`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`），
  断言：三个子面板都能切、都有行、**无 `NaN`/`undefined`**、互斥可见、`pageerror` 为空。

### 7. 现价 vs 目标价：半年窗口对照分析

- 窗口按**研报发布日期**取最近 6 个月；价格基准用体系内最新交易日收盘。
- **每机构取窗口内最新一条**为主线口径（代表「当前有效观点」），并列「全部条数」口径做对照。
- **A/H 绝不混算中位**（参与者、分析师、币种都不同）——用户会明确要求「港股和 A 股分开」。
- ★ **最有决策含义的一项是「赛跑」，不是「隐含空间」**。只报「现价比目标价低 X%」没有决策含义，
  必须同时算**同机构目标价修正幅度**与**同期股价涨跌幅**：
  - 股价涨幅 > 目标价上调幅度 → 隐含空间**收窄**（哪怕卖方在接连上调）
  - 股价涨幅 < 目标价上调幅度 → 空间**扩张**
  - 若空间扩张完全由**股价回落**造成，**不等于卖方更乐观** —— 这句必须写进结论。
- ★ **不要比「起点中位隐含空间 vs 现在的中位隐含空间」**：两端机构集合不同（早期只有少数家发声），
  换一种集合就换一个结论（实测两种集合口径给出「几乎没变」与「收窄 12pp」两个截然不同的答案）。
  **同机构配对（首条→最新）是唯一不依赖集合选择的稳健做法。**
- ★ **分歧要归因到两端**：只报「分歧 3.83×」会掩盖代表性；必须写出最低/最高是谁、什么评级，
  并附「掐掉两端各一家后的中位」作稳健性对照（实测中位常常不变 → 说明是极值在拉大倍数）。
- 现价在分布中的位置比隐含空间中位更有信息量：写「N 家里仅 M 家目标价低于现价」。

## 反面清单

- ❌ 用手工整理的「核实状态」列当作已交叉验证 —— 那是采集方自述，只能标「自述」。
- ❌ 为了让「两个源看起来一致」而去平均/调整数字。
- ❌ 用日频的一致预期去逐日累积、想补出长历史 —— 违反零缺口原则，也补不出权威值。
- ❌ 把自动链写成能改基座数值 —— 一旦如此，「核实不了的不取」就形同虚设。
- ❌ 只跑入库脚本自检就宣布通过 —— 必须有一次「独立路径重算 + 对撞已打印的数」。
- ❌ 用「现价比目标价低 X%」直接当便宜/贵的结论 —— 分母是**各市场自己的现价**，且覆盖机构不对称；
  判 A/H 相对贵贱只能用**同机构同日 A/H 双目标价之比**。
- ❌ 按 `glob` 取「最新一份」数据文件时，不排查是否存在**排序更晚但内容更旧**的文件。
  实例：日线目录里同时有 `…_2024-01-01_2026-09-18.csv` 与 `…_预热_2023.csv`，中文名在字符串排序里排在
  数字之后 → `sorted()[-1]` 拿到 2023 预热数据 → 算出一个 **+130% 的假涨幅**（真值 +19.4%）。
  取「最新一份」前先列出候选并显式排除旧窗文件。
