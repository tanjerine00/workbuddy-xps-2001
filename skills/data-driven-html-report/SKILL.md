# 数据驱动的自包含 HTML 报告

## 一句话结论

**数据不要写在 HTML 里，写到同目录的 `数据.js` 里（`window.X = {...}`），HTML 只做纯渲染壳。**

这样做的好处是「改数据 → 刷新页面即生效」**且仍然双击即用**——不需要起本地服务器。
代价是渲染逻辑从构建期（Python 生成静态 HTML）搬到了运行时（浏览器内 JS）。

**验收判据不是「页面能打开」，而是「改数据，页面真的变」。** 只验前者等于没验。

---

## 一、为什么必须是 `数据.js` 而不是 `data.json` + `fetch`

这是本工作流成立的地基，先确认这条**反直觉但确切**的事实：

| 方式 | `file://` 下 | 结论 |
|---|---|---|
| `fetch('./data.json')` / `XMLHttpRequest` | ❌ **被 CORS 拦**，报 `Cross origin requests are only supported for protocol schemes: http, https...` | 不能用 |
| `<script src="数据.js"></script>` | ✅ **同目录可加载** | **用这个** |

所以数据文件写成 JS 赋值语句：

```js
/* 数据.js —— 唯一数据源 */
window.SYS = { meta: {...}, domains: [...], materials: [...] };
```

HTML 侧：

```html
<script src="系统数据.js" charset="utf-8"></script>
```

**`charset="utf-8"` 别省**——中文数据乱码时第一嫌疑就是它。

## 二、架构长什么样

```
项目/
├── 系统数据.js              ← 唯一数据源（改这里）
├── 中芯国际分析系统.html      ← 纯渲染壳，零硬编码数据（别动）
├── 归档/YYYY-MM-DD_首版_xxx/  ← 旧版留档
└── .workbuddy/
    ├── verify_slim.js       ← 结构验收（读 数据.js，断言域/项/台账/规则数 + HTML 零泄漏）
    ├── render_check.js      ← 真机渲染验收（puppeteer：无报错 + 改数据→页面变 + 壳字节不变）
    └── verify_live.js       ← 真实文件加载确认
```

> 两个脚本分工：`verify_slim.js` 只读数据文件（秒级、无浏览器），管**结构对不对**；
> `render_check.js` 起真机 Chrome，管**页面真的动没动**。前者能跑通不代表后者没问题（反之亦然）。

**判定改造是否成功的一句话标准**：
数据更新后，**HTML 文件的字节数是恒定的**（它只是引擎），页面内容却变了。

## 三、改造既有报告的步骤

### 1. 先归档，且必须校验后才删源

```python
h_before = sha256(src); shutil.copy2(src, dst); h_after = sha256(dst)
if h_before != h_after or sizes differ: 放弃删除，报 FAIL
os.remove(src)
```

**不要先删再拷。** 沙箱里的删除守卫可能把 `os.unlink` 改道回收站并限流，
先删后拷一旦中途失败就是真丢东西。

### 2. 把数据从生成器里抽出来

典型病根：生成器（如 `build_system.py`）把数据**手抄**在源码里，运行时焊进 HTML。
抽取时保留原有的**分段结构**（域 / 板块），不要压成一坨——数据结构就是将来渲染的骨架。

### 3. HTML 改成渲染引擎

- 全部内容由 JS 从 `window.X` 生成，**DOM 里不留任何写死的数字/名称**（连 `<title>` 也由数据设置）。
- **必须写降级分支**：`window.X === undefined` 时渲染一个明确的错误框（告知"数据文件没和 HTML 放一起"），
  **不要留白页**——白页会被误判成"代码坏了"，排查方向直接跑偏。

```js
if (typeof window.SYS === "undefined") { /* 渲染错误框，写明原因与修法 */ return; }
```

### 4. 空态要做成"有信息量的空"

容器型系统在没数据时**不应该显示空白**，而应显示：**需要什么、现在缺什么、怎么给**。
本工作流的实践：数据地图（分域列出全部待填项 + 状态标签）+ 就绪度进度条 + 投喂协议。
空态本身就是这个阶段最有价值的页面。

## 四、验收：`改数据 → 页面变` 的断言法

**脚本骨架**（`.workbuddy/verify_v2.js`，puppeteer-core + 本机 Chrome）：

1. **在临时目录做副本**，绝不动工作区原件。
2. 加载 → 快照 A（DOM 断言集合）。
3. **改写副本的数据文件**（模拟一次真实数据更新）。
4. `page.reload()` → 快照 B。
5. 断言 A→B 的**差异方向与数值**，并断言 **HTML 文件字节数未变**。

必须覆盖的断言组：

| 组 | 断言什么 | 为什么 |
|---|---|---|
| 加载健康 | 无 `.err` 框、`pageerror` 0 条、`requestfailed` 0 条 | 静默失败的 JS 会让页面"看着在、其实没跑" |
| 规模 | 渲染出的条目数 == 数据文件里的条目数 | 防止只渲染了一部分 |
| **数据驱动** | 状态计数（待办 X → X−1）、KPI 卡、明细行数、进度条宽度**全部**随数据变 | 这才是判据 |
| **壳不变** | HTML 副本字节数 == 源 HTML 字节数 | 证明数据真的不在 HTML 里 |
| 标题驱动 | `document.title` 来自数据 | 防止连标题都写死 |

再补一个**真实文件加载测试**（不是副本），确认真实路径下也能跑：

```js
const URL = require("url").pathToFileURL(FILE).href;   // ← 中文路径必须这样，别手写 %E4%B8%AD
```

## 五、踩过的坑

1. **中文路径别手写百分号编码**。一律 `pathToFileURL()`；
   手写编码错一个字节就是"文件加载不了"，且现象和"路径根本不存在"完全一样，极难查。
2. **断言数字别预设**。先跑一遍把实际值打出来，再写进断言。
   我曾按"45 项"写断言、实际渲染 50 项 → 4 条**假失败**，浪费一轮排查。
   更稳的写法：`const EXPECT = A.rows;` 然后断言 `B.rows === EXPECT`。
3. **别把"清空数据"做成"删文件"**。用户的"把数据删掉"通常指**内容清空**，不是删掉载体。
   正确做法：旧版归档 + 新壳就位，并**在交付说明里讲清"什么被移走了、在哪能找到"**。
4. **同一个文件的多处修改别发多个并行 Edit**——它们互相覆盖且**全部报 success**。
   改用一次性幂等补丁脚本：逐组核对"旧串命中次数"，全中才写回，写完回读校验。
5. **空容器要显式说明"空是有意的"**，否则会被当成"没做完"。
   本项目里结论区为空是设计：**结论必须站在已交叉验证的数据上——先有料，再有话。**
6. **数据字符串里的 `**强调**` 会被原样显示**（2026-09-20 实测）。
   数据文件是人手写的，天然会用 markdown 的 `**重点**` 标关键数字；而渲染壳若只做 `esc()`
   （转义 `&<>"'`），`**` 就会**字面出现在页面上**（实测一次 12 张结论卡全带 `**`，很扎眼）。
   修法：加一个显示层函数，**先转义、再转换强调**，然后把文本渲染点的 `esc(` 换成它：
   ```js
   var rich = function(s){ return esc(s).replace(/\*\*([^*]+)\*\*/g, "<b>$1</b>"); };
   ```
   验收断言：`document.body.innerText.match(/\*\*/g)` 出现次数 **== 0**（正常应为 0）。
   ⚠ 别直接改 `esc` 本身——语义会变成"转义+格式化"，调用点全被隐式改变；加 `rich` 更安全。
7. **用 Python 打补丁会静默改行尾**（2026-09-20 踩到）。
   文本模式 `io.open(p, "w", encoding="utf-8")` 会把 CRLF **写成 LF**。
   若项目文件（HTML/JS/批处理）是 CRLF，字节数会**莫名变化**（本例 26986 → 26680），
   很容易被误判成"内容被改坏了"。**修法**：读时记下原行尾，写回时还原——
   ```python
   txt = io.open(p, encoding="utf-8").read()
   NL = "\r\n" if "\r\n" in txt else "\n"          # 记住原行尾
   ...处理时先归一成 \n...
   io.open(p, "w", encoding="utf-8", newline="").write(out.replace("\n", NL))
   ```
   写完复核 `CRLF 数 == LF 数`。**同时提醒**：字节数变化要能一句话解释（本例 = 行尾转换），
   解释不了就说明真改坏了。
8. **瘦身数据后，必须审"静态文案"是否自相矛盾**（2026-09-20）。
   数字对了 ≠ 文案对。本例：数据地图从"缺口清单（展示缺什么）"改成"已核验清单（只列零缺口数据）"后，
   那段的 lead 还写着"让你知道**系统现在缺什么**、哪些缺口卡着结论出不来"——**在 0 待投喂的新状态下成了假话**。
   → **改数据语义时，同时 grep 渲染壳里的引导语 / 小标题 / 空态文案**。
   通用判据：页面上任何一句"我们缺 X / 还没做 Y"，都要能对应到数据里的一个非零计数。
