## 环境事实（跨项目通用，踩过坑）

- ★ **不要在同一条消息里对同一个文件发多个 `Edit`**（2026-09-16 实测）：它们并行执行**互相覆盖**，
  工具**全部报 `success`**，实际只落盘一部分（17 个 Edit 只进去一部分，文件字节数还涨了）。
  → 同一文件的多处改动改用**一次性幂等补丁脚本**：单次原子写 + 逐组核对"旧串命中次数" +
  落盘后回读 + 语法自检（文本看括号配平，HTML 看标签配平），**自检不过就不写回**。
  补丁脚本自身三个坑：①"旧串必须为 0"对**追加式**替换是错的（要用 `count(旧)==count(新)×内含次数`）；
  ②"括号前后必须相等"错（新增内容本来会让计数涨，只要求各自配平）；③本机 stdout 默认 **GBK**，
  且 `-E` 会**忽略** `PYTHONIOENCODING` → 必须在脚本里 `sys.stdout.reconfigure(encoding="utf-8")`。
- **Bash 里的中文不可靠**：Git Bash 会转码，`grep`/`echo` 的中文模式串会给出**假 0 或假命中**
  → 搜中文一律用内置 Grep 工具。
- ‼ **curl 走沙箱代理访问 HTTPS 站点报 exit 35（CRYPT_E_REVOCATION_OFFLINE）**（2026-09-27 实测，
  aihot.virxact.com 首次连接就崩）：Windows curl 用 schannel，经代理隧道后吊销检查失败。
  → **加 `--ssl-no-revoke` 即通**。另有：API 类站点默认 `curl/X.Y` UA 会被目标 nginx 挡 403，
  需带浏览器 UA（`-H "User-Agent: Mozilla/5.0 ..."`）。
- ‼ **【硬性操作纪律，2026-09-20 踩过，代价真实】凡是含反引号或中文的 Python 代码，
  一律先用 Write 工具落成 `.py` 文件，再用 Bash 执行该文件——绝不用 `python -E -c "..."` 内联。**
  原因：Git Bash 会对**双引号内**的反引号做命令替换，把 `` `体系/*.md` `` 这类路径当命令执行，
  然后把整段替换成空串 → **写出来的文件缺词**。
  2026-09-20 实例：往日志里追加带反引号的段落，5 处内容被静默吃掉，还需事后用 mtime 逐个核实
  有没有文件被误执行。**写文件永远走 Write/Edit 工具，shell 只负责执行已落盘的脚本。**

- **WorkBuddy/CodeBuddy 沙箱会注入一个删除守卫**：子 Python 进程的 `PYTHONPATH` 被加上
  `<安装目录>\cli\vendor\shim`，其中的 `sitecustomize.py` 把 `os.unlink/rmtree/pathlib.unlink`
  全部改道回收站，并按"每轮 50 个"限流。后果与对策：
  - `pip install` 覆盖包文件超阈值会直接 `SystemExit(1)` 猝死 →
    **装包一律用 `python -E -m pip ...`**（`-E` 忽略 PYTHON* 变量，shim 进不来）。
  - 应用进程（如 PaddleX 下载/清理模型）会被打断 → 父进程设
    `CODEBUDDY_SAFE_DELETE_ENABLED=0`（必须在 Python 启动前设，脚本内设已经太晚）。
  - 该 shim 的报错会撒谎：打印 `SAFE_DELETE_FAIL_CLOSED / "reason":"trash-failed"` 但文件其实
    已删。**用列目录复核，不要信返回值。**
  - `pip install --upgrade pip` 在新建 venv 里会卡死并留下 `~ip` 垃圾目录，**直接跳过这步**。
- **沙箱里删文件的正确姿势（2026-09-12 实测，卸载 PaddleOCR 时踩的）**：
  - `Add-Type` 与 `New-Object -ComObject Shell.Application` **都被安全策略拦下**（报错文本都写成
    "Add-Type compiles and loads .NET code at runtime"，与实际操作对不上）。
    → **别指望在 PowerShell 里加载程序集或走 COM 回收站**。
  - **硬删除**：`[System.IO.Directory]::Delete($p,$true)` / `[System.IO.File]::Delete($p)`。
    不受 shim 拦截，速度正常 —— 868MB / 2 万个文件的 venv **6 秒**删完
    （对比：pip 卸载同量级要 20~30 分钟）。
  - **真想进回收站**：反过来利用 shim —— 用**不带 `-E`** 的 Python 子进程（`PYTHONPATH` 里带 shim）
    调 `os.unlink`，它会改道回收站。**删前必须断言 `shim` 在 `sys.path` 上**，否则就成了永久删除；
    且只适合少量文件（<50 个，超阈值会被批量删除守卫打断）。
  - **删任何部署前先盘点目录**：里面可能有用户自己的文件（PaddleOCR 那次就有 3 张微信图片
    和识别结果），别一句"全部删除"把用户数据一起带走。
- **PowerShell 工具的 stdout 不回显**，必须 `输出写文件 → 用 Read 工具读`。
  且 `(& exe ...) | Add-Content` 会缓冲到进程结束才落盘，"没输出"不等于"卡住"；
  判定进度要看 site-packages 体积、进程 CPU、pip 临时目录。
- **PowerShell 5.1 的 `Start-Process` 在本机不可用**（2026-09-12 实测）：
  起任何子进程都会直接报 `已添加项。字典中的关键字:"Path"所添加的关键字:"PATH"`——
  环境里同时存在 `Path` 和 `PATH`，PS 5.1 构建环境块时崩掉，**子进程根本没被拉起**
  （表现是"任务秒退、日志 0 字节"，极易误判成目标程序静默失败）。
  → **起子进程一律改用 bash 的 `>` / `2>&1` 重定向**，增量落盘且不受此 bug 影响。
- **Bash 工具 PATH：2026-09-14 已永久修复。** 根因：WorkBuddy 用 PortableGit 的
  `bash.exe` 起 shell，却没把它的 **`usr/bin`** 放进 PATH；非交互 bash **只读 `BASH_ENV`、
  不读 `~/.profile`**（往那里写 PATH 修复实测无效）。shim 第 3 行只有 `dirname` 是外部命令依赖，
  它一挂，`safe-delete` / `brokered-sandbox` 两个守卫脚本的 source 也被跳过。
  → 已把 `PortableGit\versions\1.2.0\usr\bin` + `MinGit\usr\bin`（抗升级兜底）追加到
  用户级 PATH 末尾，**重启 WorkBuddy 后 `ls/grep/head/tail/dirname/find` 全部可用**。
  若复发（PortableGit 换版本目录），照技能 `workbuddy-bash-path-fix` 补一条。
  不要再退回"命令前 export PATH"的绕法。
- **`python -E` 是双面的**：装包时必须加（挡沙箱 shim）；但**启动器/正常运行时不能加**——
  `-E` 会连 `PYTHONUTF8`/`PYTHONIOENCODING` 一起忽略，正好破坏 Windows 中文输出。
  典型翻车：脚本 print `✅/🚀` 等 emoji → GBK 控制台 `UnicodeEncodeError` 直接崩，
  **而且崩在 print 上会留下"目录已建、内容没写"的半成品**（2026-09-13 跑 expert-manager
  的 init_expert.py 就是这样，重跑报 "directory already exists"）。
  正确姿势：去掉 `-E`，改用 `$env:PYTHONIOENCODING="utf-8"; $env:PYTHONUTF8="1"`。
- **压缩图片不用装 Pillow**：本机 `C:\Users\zyx32\bin\ffmpeg.exe` 现成可用，
  `-vf scale=512:512:flags=lanczos -compression_level 100` 能把 1.37MB 的 1024px PNG
  压到 394KB（专家头像 ≤500KB 这类硬限制直接这么过）。
- 环境变量 `HTTPS_PROXY=http://127.0.0.1:10432` **只在 agent 进程环境里**，
  不在 User/Machine 级 → "我这边能通"不等于"用户双击时能通"，下网络结论要说明这个差异。
- **`requests` 的代理行为（2026-09-12 实测，比之前记的更完整）**：
  - `trust_env=True`（**默认**）时走 `urllib.request.getproxies()`，
    在 Windows 上**会读注册表代理**（本机 mihomo = `127.0.0.1:7890`），
    不只是环境变量。→ 想让某个源**直连**，必须显式 `session.trust_env = False`。
  - **不要开全局 `HTTP(S)_PROXY`**：那会把本该直连的境内端点也绕境外代理。
  - 正确姿势是**逐源路由**：境内源用 `trust_env=False` 直连，需要翻墙的源单独配代理
    （库支持的话用库自己的 config，如 `yf.config.network.proxy`）。
  - 本机代理端口实测：7890/7892 可用；7891 连得上但不代理；7893 超时不存在。
- **Edit 工具"谎报成功"的规律（2026-09-12 补充）**：
  **长 `old_string` 更容易失败**（尤其含空行/连续行时），改完**必须 grep 复核**。
  可靠做法：用**单行唯一 anchor** 做 Edit，一次改一处；改完 grep 确认落盘。
- **本机 HTML 渲染 / 截图链路（2026-09-13 实测）**：`agent-browser` **未装**——为截一张图
  去下 ~500MB Chromium 不划算；直接用**本机 Chrome**
  `C:\Program Files (x86)\Google\Chrome\Application\chrome.exe`（只装了 32 位版）。
  `puppeteer-core` 已在托管工作区
  `C:\Users\zyx32\.workbuddy\binaries\node\workspace\node_modules`，
  跑法：`NODE_PATH="<workspace>/node_modules" "<managed node 22>/node.exe" script.js`。
  复核图表/版式优先 `elementHandle.screenshot()` **按元素截**，比 fullPage 巨图看得清；
  `page.evaluate` 取 `documentElement.scrollWidth` 可顺带验有没有横向溢出。
- **手算坐标的 SVG 必须渲染截图复核**（2026-09-13 踩坑）：首版把网格线画在估算位置、
  刻度标签写整数，两者斜率不一致，光看代码发现不了，是截图后才揪出来的。

## WorkBuddy 的任务机制：怎么把「已有目录」变成一个任务（2026-09-15 实测）

- **任务 = `~/.workbuddy/workbuddy.db` 里 `sessions` 表的一行**，按 `cwd` 区分。
  一个目录**只有被应用自己登记过**才会出现在任务列表里；光在
  `C:\Users\zyx32\WorkBuddy\` 下建目录（哪怕带 `.workbuddy/memory/`）**不会**变成任务。
  → 想从外部"插一条记录让目录变成任务"是高风险动作：应用常驻运行、
  `workbuddy.db-wal` 常有几百 KB 未落盘，写了容易状态冲突。**默认别干。**
- **正确做法（官方路径）**：`选择工作空间` 面板里有 **`打开本地文件夹`**——这才是选
  任意已有目录的入口。语言包原文（`resources/app.asar` 内）：
  ```
  chatInput.workspacePicker.label            = 选择工作空间
  chatInput.workspacePicker.searchPlaceholder= 搜索工作空间
  chatInput.workspacePicker.createWorkspace  = 新建工作空间
  chatInput.workspacePicker.openLocalFolder  = 打开本地文件夹   ← 选已有目录用这个
  chatInput.workspacePicker.noWorkspace      = 不使用工作空间
  ```
- ⚠️ **这个挂件只在「首页 / 新建任务页」的输入框下方，任务对话页（详情页）里已被去掉**
  （app.asar 内的源码注释写明了这一点）。在对话页里翻遍也找不到——我因此指错过一次路。
- 「新建任务」按钮 = **顶部标题栏的加号图标**（`conversation.newTask`，
  `data-track-id="agent_new_task_button_clicked"`），不是输入框左下角。
- 设置里的 `settings.workspacePath` 是"新建任务的默认存储**父目录**"，
  **不能**把某个已有目录指定成当前任务。
- **兜底方案**（UI 上实在找不到入口时，零风险）：让用户点加号新建任务 →
  应用自动生成 `WorkBuddy\<时间戳>\` → 再把书稿/文件整包搬进去。
  搬迁脚本模板见 `C:\Users\zyx32\AppData\Local\Temp\move_to_newtask.py`
  （含"只认 2 小时内新建的空目录"的防误判逻辑 + 路径重写三种斜杠形态）。
- **查界面文案的可靠办法**：不要在文档里猜，直接对
  `C:\Users\zyx32\AppData\Local\Programs\WorkBuddy\resources\app.asar`（284 MB）
  分块搜 UTF-8 关键词（8 MB 块 + 4 KB 重叠），能拿到语言包原文和源码注释，比文档准。

## 东方财富妙想 MCP：资讯检索会返回「日期错配」的旧文（2026-09-13 实测，重要）

- `mx_finance_search_news` / `mx_finance_search_notice` 的结果里，**存在内容属于更早时期、
  发布时间却被标成当前日期的条目**。实测遇到两条：
  - 某媒体（标 2026-08-20）写"9/9 中芯国际复牌跌 10.26%、收 102.99 元，9/8 公告定增
    收购中芯北方剩余 49% 股权"；
  - 某公告汇总（标 2026-09-08）写"中芯自 9/1 起停牌，筹划收购中芯北方少数股权"。
  实际：该收购 **2026-06-23 已完成**（公告 2026-025），9/1-9/11 A 股每日均有成交，
  9/9 实收 120.51 元。→ 内容实为**约 2025 年 9 月**的事件。
- **采信规则（必须执行）**：
  1. 资讯/公告的**日期不可单独作为时效依据**，必须与**行情数据**（该日是否有成交、
     价格是否落在区间内）和**结构化公告库**交叉验证。
  2. 出现"停牌/复牌/大跌 X%"这类**剧烈事件描述**时，先用行情数据核对该日
     涨跌幅与成交量——对不上就判定为旧闻，**不得写入结论**。
  3. 若已误采信，必须在报告里**显式列出数据质量警示**并说明矛盾点（这是对用户负责的
     必要动作，不是可选项）。
- 口诀：**数值类数据（行情/财务/估值/港股通）可靠度高；文本类检索（新闻/研报/公告）
  必须验日期。** 妙想的数值查询工具本轮未发现口径问题。

## 本机硬件（2026-09-11 实测，决定方案可行性时必看）

- **CPU**：Intel Core i7-8550U（2017 年低压笔记本 U，4 核 8 线程，1.8GHz 基频）

  - 涉及"本地大模型 / 本地 LLM 总结"的需求，在这台机器上基本不现实，要先说明硬件瓶颈。

## 本机网络环境事实（2026-09-19 实测，做数据抓取必看）

- 环境预置 `HTTP_PROXY=http://127.0.0.1:24820`（沙箱出口）。**它挑主机**：
  东财 `datacenter-web`、上交所、新浪、腾讯能过；东财 `push2his` 走代理直接被拒。
- **"直连档"必须把 `HTTP(S)_PROXY` 从环境里删掉**——只设 `NO_PROXY="*"` 是**无效的**
  （urllib 的 `proxy_bypass` 不认这个通配符）。这是我一开始"直连"其实没直连的原因。
- ★ **`push2his.eastmoney.com` 是间歇性被重置，不是永久封禁**：同一 URL 前一刻
  `RemoteDisconnected`、后一刻 HTTP 200。→ **必须多通路 × 多重试**（直连/代理轮流，
  至少各 3–4 轮），**不能因一次失败就判定"数据拿不到"**。但也**不能只依赖它**。
- **稳定替代源（实测可用）**：
  | 要什么 | 用什么 |
  |---|---|
  | 个股资金流历史（含超大单净额） | 新浪 `vip.stock.finance.sina.com.cn/quotes_service/api/json_v2.php/MoneyFlow.ssl_qsfx_zjlrqs?page=1&num=200&sort=opendate&asc=1&daima=sh688981` |
  | 日线（不复权） | 新浪 `money.finance.sina.com.cn/.../CN_MarketData.getKLineData?symbol=sh688981&scale=240&ma=no&datalen=200` |
  | 日线（可指定前复权） | 腾讯 `web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh688981,day,,,320,qfq` |
  | 股东户数 / 龙虎榜 / 大宗交易 | 东财 `datacenter-web`（akshare 对应函数） |
  | 融资融券明细 | **直连**上交所 `queryMargin.do` + `stockCode=<代码>`（**不要用 akshare**：它只取第 1 页 2000 行，个股常常 0 命中；单请求约 8 秒 → 用 8 路并发，127 天约 1 分钟） |
  | 港股行情/南向 | 新浪/腾讯港股接口、港交所 hkexnews |
- **万得（Wind Alice）连接器已接入**（2026-09-19，账号有 2,298.8 积分 / 日 998 次）。
  端点 `https://mcp.wind.com.cn/vserver_workbuddy/mcp/`，鉴权头 `Bearer ${WIND_API_KEY}`
  由客户端从 `app/connector-keys/` 解密注入（**环境变量里没有，也不该有**）。
  ⚠ **连接器在会话中途启用时，其工具不会挂进当前会话的 deferred 索引**——
  `ToolSearch` 搜不到、`DeferExecuteTool` 报 "not found"。
  → **必须开新会话才能用**，不是配置错误。用户已定优先级：**东财主 → 万得次 → 新浪/腾讯验证**。
- ✗ **仍缺**：妙想 MCP 积分已用完（2026-09-19）；本地未接入 SBL（股票借贷）数据。
- **★ 妙想授权/密钥的两层结构（2026-09-29 查清）**：
  - **① 妙想 Skills 的 `MX_APIKEY`（`mkt_` 前缀）** = 唯一被 skill 读取的凭据，只写进 `apikey` 请求头，
    端点 `mkapi2.dfcfs.com/finskillshub/api/claw/query`。**本机存在 Windows 用户级环境变量**
    （注册表 `HKCU\Environment`，非 HKLM）⇒ **已是「不废」形态**：重启/关机/换会话/新终端都在，
    **不存在续期一说**。（查法：Python `winreg` 读 HKCU\Environment——`reg.exe` 被沙箱黑名单挡。）
  - **② 服务端没有「有效期」可设**：官方错误码只有 **113 次数达上限 / 114 密钥失效 / 115 未携带 / 116 不存在**
    （+404 模拟组合未绑定），**无「过期」类错误码**；接口响应头/体亦无过期字段。⇒ 它按**配额**与
    **可被作废**终止，不是按时间过期——**客户端无法改成不过期**，那是平台策略。
  - **③ 连接器侧（`mx-ds-mcp` 等 OAuth 型）**：凭据**加密存本地**（`~/.workbuddy/app/connector-keys/`
    那把 32 字节 `.key` 是解密密钥，不是令牌），客户端运行时解密 → 注入 `Authorization: Bearer …` 到
    本地代理 `127.0.0.1:16202`。**会话里看到的 Bearer 是会话级的**（每会话都换，属设计非过期）；
    平台令牌**没有「永不过期」用户开关**，失效就在连接器页重授权。
  - 失效恢复：`[Environment]::SetEnvironmentVariable("MX_APIKEY","<新key>","User")` 后**须新开终端/会话**生效。

- 新浪资金流字段口径：`netamount`=总净额、`r0_net`=超大单净额、`changeratio` 是**小数**
  （×100 才是百分比）、`turnover` 字段口径**未核实，不要当换手率用**。

### 两个必踩的数据口径坑（2026-09-19 实测）

1. ★ **妙想/东财日线序列里含"停牌占位行"**：停牌期间仍保留日期行，开高低收全部相同、
   **量额为空（NaN）**。中芯国际 2025-09-01~09-08 就是这样 6 行。
   → **滚动求和/滚动 VWAP 前必须先剔除 volume 为空的行**，否则 `cumsum` 后整段变 NaN。
   → 剔除后「N 日 VWAP」指 N 个**实际交易日**。新浪/腾讯的 K 线**不返回**停牌日，
   所以它们与妙想的行数天然对不上——**这不是数据错误，别当差异处理**。
2. ★ **东财「股东户数」是 A 股口径，定期报告「股东总数」是 A+H 口径**：
   中芯国际 2026-06-30 东财给 287,089（A 股），半年报公告给 296,744（总数，其中港股 9,655）。
   → 两份材料户数对不上时，**先比口径，别急着判谁错**。

**已验证：腾讯 K 线独立复核过本地日线**——2026-09-18 开 120.78 / 收 122.00 / 高 123.43 /
低 119.93 / 量 38,721,991 股，与妙想底稿逐项一致。
