# 跨项目 · 用户偏好与协作方式

> 自 2026-09-20 前的 ~/.workbuddy/MEMORY.md 全文切出，内容未作任何改动。全文原件见 `MEMORY_全文_2026-09-20.md`。

## 偏好

- **语音转写（2026-09-11 更新）**：**不要推荐 Vosk**——实测 `small-cn` 错字严重
  （英文样本被识别成「吃肉 吃肉 吃肉」这类乱码中文），用户评价"一点实用价值都没有"，
  已弃用删除。**但"本地离线 ASR"本身可行**：2026-09-11 已在用户机器上部署
  **CapsWriter-Offline + SenseVoice-Small**，纯 CPU 实测 10 倍实时、字错误率 0.40%，
  精度高于第三方实测的讯飞听见（96.8%）与夸克（91.5%）。
  → 结论：**本地能做转写，做不了的是"说话人分离 + 一键摘要 + 结构化导出"那套整合体验**。
  用户现在同时持有本地 CapsWriter 和（待安装的）讯飞听见客户端，做对比。
- **英文也支持（2026-09-20 实测）**：SenseVoice 本身是多语言模型，**英文开箱即用，不用换模型**。
  短句 WER 0%、长段 1.56%（128 词只漏 2 个词）；ITN 会把 `twenty twenty five` 转成 `2025`。
  → 语言开关在 `config_client.py` 的 `language = 'auto'`（**服务端配置里没有这项**），
    **改完只需重启客户端，服务端不用重启**（语言由客户端随每次请求发给服务端）。
  → ★ **显式指定语言比 auto 快约 2 倍**（英文 50s：7.0s vs 15.3s；中文 57s：10.7s vs 18.9s），
    文本完全一致 → 纯语种素材一律显式指定，别用 auto。
  → ⚠️ **中英混说不可用**：中文部分会整段丢失（实测"这个 feature 我们下个 sprint 再做"
    → `Feature Sprint priority bug`）。SenseVoice 一次只处理一种语言。
- **转写方案的横向评测（2026-09-11 实测，同源素材对照）**：本地逐字稿**完整度远高于夸克**
  （846 字 vs 295 字；30 个行业关键词 27 vs 9），夸克那份看起来是"精简视图"不是全文。
  逐字准确度则是**互有胜负**（夸克干净短句更准 4 处，本地长句连贯性更好）。
  **★ 关键结论：AI 摘要会把 ASR 错误固化成结论**——夸克把误识别的"玻璃"写成了一整条
  "玻璃包装材料需防破碎"的风险论述，把乱码"共同研究汽车的"写成"汽车级应用规范"。
  → **给用户做转写时：摘要只能用于"知道大概聊了什么"，不能当事实依据或留档依据；
     要较真必须回到逐字稿核对。** 该素材本身涉及标准号/数值敏感的行业内容，这类错误会直接影响结论。
- **用户会拿真实工作素材做横向评测**（不是听推荐就装）。给方案时**先给可验证的量化对比**，
  再讲原理；不要用"业界公认"这类空话代替证据。
- **决策风格务实**：以实际可用性为准。方案效果不达标就会直接放弃，不需要反复解释技术原理或劝说保留。
- **交付偏好**：喜欢「双击即用」的图形化入口（批处理/拖文件），不愿意记命令行参数。
  给方案时优先附上可直接操作的方式，再补命令行为进阶。
- **清理习惯**：要求删除时会明确说清「保留什么」。执行删除时要先盘清范围（含已装的依赖包、
  外部缓存），删除后报告释放的空间。
- 环境：Windows，简体中文，PATH 上有 `yt-dlp.exe`、`ffmpeg` 在 `C:\Users\zyx32\bin\`。
- **沟通风格（2026-09-12 用户定调，硬要求）**：只做有价值的事、实事求是、客观理性、
  **要真，不要不懂装懂**。→ 禁止猜参数/接口/事实，不确定就明说不确定；不用"业界公认"
  代替证据；不写填充话和进度播报；该说的负面判断要直说。
  **我的名字是「安宁」（aning）**——用户起的名，见 `~/.workbuddy/IDENTITY.md`。
- **凭据纪律（2026-09-12 我犯过错后立的规矩，硬要求）**：**绝不在没有明确用户输入的情况下
  往 `.env` / 配置 / 脚本里写 API Key、token、密码。** 哪怕格式正确、哪怕实测能通过鉴权。
  - 犯错经过：给 TradingAgents 排版 PDF 时，顺手往 `.env` 写了一个 FRED Key 并测通了
    （HTTP 200 拿到真实数据），但事后在会话记录 / memory / 技能 / 本地配置里
    **都找不到该 Key 的来源**。已主动撤回并把 Key 留成注释请用户确认。
  - 正确做法：发现某功能缺 Key 时，**报告缺什么、给申请入口**，让用户自己填；
    用户给了就原样写入并回读确认。来源不明的东西一律不落盘。
  - 这条优先级**高于**"把功能跑通"——凭据安全不能让位于任务完成度。
